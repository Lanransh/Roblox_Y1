# MiniStudio → Roblox 框架

来源：`F:/MiniGame/Studio_Y3/Code/ServiceNodes/MainStorage/Scripts/Framework`。
迁移范围为通用框架，不包含源项目的玩法、地图、MiniStudio 节点 JSON、开发者白名单或美术资源。

服务端入口：公共层 → FS 类 → 服务注册 → 玩家数据加载 → 客户端 Ready → 玩家对象与组件 → 初始数据同步 → ServerReady。

客户端入口：公共层 → FC 类 → 本地玩家对象与网络订阅 → 等待服务注册完成 → Ready 握手。重复 Ready 不会重新创建玩家。

保留 `_G.FX`、`_G.FC`、`_G.FS`、`_G.Provider` 和类注册约定；Roblox 模块不能通过其他脚本的裸全局变量取值，业务模块应显式声明 `local FX = _G.FX`。`_G.MS.MainStorage` 仅作为 ReplicatedStorage 的旧名称别名；新代码直接使用 Roblox 服务名称。

## 项目接入

新增服务端组件继承 `FSPlayerCompClass`，客户端组件继承 `FCPlayerCompClass`，UI 组件继承 `FCUICompClass`。在项目玩家对象/客户端入口中 `AddComponent("类名")`。组件的 `OnUpdate(serverTime)` 每秒执行；构造时绑定事件，析构时释放连接、节点和任务。覆盖 `Ctor/Dtor` 时显式调用 `Super`。

玩家字段由 `FrameworkConfig.PlayerData` 定义 `Type/Key/DefVal/Sync/KVTable`；可选 `KVResetType` 为 Daily、Weekly 或 Monthly。日期按 Roblox 服务器 UTC 计算。服务端调用 `SetNumber/GetNumber/SetFlag/GetFlag/SetTable/GetTable`；表字段应通过 `SetTable` 提交，单纯修改 `GetTable` 返回的副本不会落盘。写入 nil 表示恢复字段默认值。客户端通过玩家对象读取或 `WatchDataChanged` 订阅。

道具配置需包含 `Id/Type/MaxStack`；可使用 `UseHandler` 注册服务端使用处理器。需要显示在原生背包的道具配置 `Name/ToolShape/ToolColor`，服务端根据存档创建 Tool，客户端通过 `Tool.Activated` 请求使用。

引导配置格式保留 `groupId = { startEvent, steps = { { finishEvent, target } } }`。业务事件从服务器玩家对象发布；客户端不能直接提交“完成引导”请求。

### UI 差异

- 节点类型用 `Frame/TextButton/ImageButton/TextLabel/ImageLabel/ScrollingFrame`。位置和尺寸用 `UDim2`，轴心用 `AnchorPoint`，文字用 `Text`，图片用 `Image`，按钮事件用 `Activated`。
- 背包和快捷栏直接使用 Roblox 默认 Backpack；框架格号是服务端存档身份，不对应屏幕上的数字键位置。
- `UIAnim:FadeIn/FadeOut` 使用 CanvasGroup；缩放使用 UIScale；进度动画修改填充节点的 `Size.X.Scale`。
- 声音 ID 必须为有权限的 Roblox `rbxassetid://...`；`sandboxId://` 资源不能直接使用。MiniStudio 的引导特效索引不再控制箭头样式。

### 通用奖励、提示弹窗与好友

这三项从 Y3 的通用业务能力中提取到框架，按 Roblox 重写并接入启动。没有迁入 GM、好友倍率、离线奖励或其他玩法规则。

**奖励（仅服务端）**：项目玩家对象已挂载 `FSRewardCompClass`，通过 `player:RequireComponent("FSRewardComp")` 取得。提供 `CanAddRewards / AddRewards / CanConsumeRewards / ConsumeRewards`，返回 boolean。

```lua
local rewards = player:RequireComponent("FSRewardComp")
rewards:AddRewards({ { Type = "Item", ItemId = 1001, Count = 12 } })
-- 1001 需先在 FrameworkConfig.Items 定义；超过 MaxStack 自动拆分堆叠。
```

货币不预设游戏字段。在 `FrameworkConfig.PlayerData` 定义 number 字段后，将 `RewardCurrencies.Money` 设为该字段的配置名，例如 `"Coins"`。奖励格式为 `{ Type = "Money", Count = 5 }`；多币种用 `Currency` 指定映射名。默认映射为空，未配置货币时拒绝货币奖励。

整批先检查道具容量和货币余额，重复货币项（包含映射到同一字段的别名）会合并校验；未知类型、非正整数、NaN、无穷大、稀疏列表和余额溢出均拒绝。支持 Y3 的 `itemId/count/extraData` 小写字段，`Type` 仍为 `Item/Money`。独立词条道具按每件一个格子发放，并复制词条表。扣除按 ItemId，不支持按 ExtraData 精确选择，传入 ExtraData 的扣除请求会被拒绝。

奖励操作使用已有玩家档案和背包，不提供客户端直接领奖协议，也不扩展为跨服务事务。项目覆写的数据变化回调、手持处理器应保持无 yield；外部服务调用和自定义持久化失败不由本组件回滚。

**提示/弹窗（客户端）**：默认挂载 `FCCommonUICompClass`，创建原生 UI 并默认隐藏。已有服务端 `player:ShowTips(text, duration)` 消息现在会实际显示。客户端用法：

```lua
local ui = _G.FC.PlayerObject:RequireComponent("FCCommonUIComp")
ui:ShowTips("操作完成", 2)
ui:ShowConfirm({
    Desc = "确认继续？",
    ConfirmBtnTxt = "继续",
    CancelBtnTxt = "取消",
    ConfirmCB = function() print("确认") end,
    CancelCB = function() print("取消") end,
})
```

`ShowTooltips({ Desc, ConfirmBtnTxt, ConfirmCB })` 保留 Y3 的单确认说明弹窗语义；`ShowConfirm` 显示确认和取消。`HideTooltips()` 仅关闭，不执行回调。新弹窗替换旧弹窗，旧回调丢弃；点击先关闭并清理回调，再调用选中的回调。提示替换时取消旧定时器，析构时清理计时器、按钮连接和 ScreenGui。确认回调是本地交互入口，涉及发奖或扣款时仍需业务服务端校验。

**好友**：`FS.FriendService` 使用服务器 `Players:GetFriendsAsync(userId)`，遍历所有 FriendPages 后才提交列表。客户端不上传好友 ID，不决定关系。登录查询、玩家进出房更新同服列表，每 120 秒重新查询平台；平台可见性和缓存决定关系变更何时可见，不保证即时刷新。

- 服务端 `GetFriendIds(playerId)` 返回完整好友 ID 列表副本；`IsFriend(playerId, otherId)` 返回 boolean；`GetFriendCountInRoom(playerId)` 返回同服好友数。尚未加载或查询失败均返回 nil。
- 两端 `GetState()` 返回 `{ ids, status, revision }`；服务器需传入 playerId。`ids` 只包含同服好友；status 为 `Loading / Ready / Unavailable`。失败时保留上次同服快照供展示，但不可当作当前已验证关系。
- 客户端通过 `FC.PlayerObject:RequireComponent("FCFriendComp")` 读取状态；变化发布玩家事件 `FriendStateChanged(state)`。晚订阅组件先调用 `GetState()` 获取当前快照。
- `C2S_GetFriendState` 只返回引擎认证调用者的缓存，不发起平台查询；`S2C_FriendState` 下发快照。版本号防止旧快照覆盖新快照，会话身份检查防止离服期间的异步结果污染重进玩家。

### 存档与支付

`StorageConfig.StudioMemory = true` 为默认值，仅在 Studio 生效。内存模式执行同样的档案和锁逻辑，同一次试玩内保存/重载有效，停止试玩后清空。它不是云存档测试，也不会自动在云请求失败时启用。正式服务器始终使用 DataStore；加载失败或档案格式错误会拒绝登录，避免覆盖旧数据。

正式接入前设置自己的 DataStoreName；真实持久化验收需已发布的测试体验和相应 API 权限。MiniStudio 的旧云档案不会自动导入 Roblox，玩家身份与数据来源也不同。

`FrameworkConfig.Goods[ProductId]` 定义商品及 `BuyHandler`。服务器在 `_G.Provider.BuyHandlers` 注册处理器；`CanBuy` 必须为纯判断，`Buy` 必须无 yield 且只修改当前玩家的持久化档案。不要在处理器内调用外部服务、另一个 DataStore 或向其他玩家发奖，这些操作无法随档案回滚。Receipt 标记与玩家奖励在同一记录中保存，保存成功才返回 PurchaseGranted。客户端提示结束不是发奖依据。

调用 `FC.PlayerObject:RequireComponent("FCCommonUIComp"):ShowDeveloperBuyUI(productId)` 发起已校验购买提示。框架占用唯一 `MarketplaceService.ProcessReceipt` 回调，接入其他商品系统时应在本服务内合并路由。源项目的 GM 直发商品协议和固定开发者 ID 未迁入。
