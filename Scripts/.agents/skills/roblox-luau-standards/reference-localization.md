# 本地化维护规则

## 数据保护与写入流程（必须遵守）

这些规则适用于 Studio LocalizationTable、本地翻译文件和 CSV，以及云端翻译表。普通文案修改只授权新增或修改目标条目，不授权删 Key、删语言、清表或重建文件。项目只维护英文，不代表可以删除已有其他语言译文。

1. **确认目标并保存修改前数据。** Studio 目标是编辑态 `game.ReplicatedStorage.Shared.Localization`；先核对 Studio、实例类型和源语言。文件操作核对实际路径，云端操作核对目标体验和表。写入前保存可恢复的完整原始数据，包含所有条目及语言值；备份不得覆盖原文件，也不能只存在于被截断的工具输出中。Studio 数据不受脚本仓库 Git 保护，不能把 Git 当成它的备份。
2. **读取异常就停止写入。** 读取失败、超时、结果截断、解析失败或原有表意外为空时，不用 `{}`、空数组、空文件或仅含本次 Key 的列表兜底。先确认原因；找不到实例或文件时也不自动创建空表替代。
3. **明确增量。** 列出本次新增或修改的 Key 及字段；已有条目仅修改本次涉及的英文源文案、英文值和参数示例。保留无 Key 的已有条目、Context、未知字段及其他非目标字段；Values 只更新目标英文值，已有非英文译文保持不变。英文变化导致译文可能过时时报告云端待更新，不自行翻译或清空。遇到重复 Key 或无法唯一匹配的条目，先解决歧义，不自动合并或去重。
4. **按条目写入。** 日常维护禁止 `SetEntries({})`、清空后重建、销毁重建 LocalizationTable、批量 RemoveEntry/RemoveTargetLocale，以及用仅含本次条目的数据调用 SetEntries。优先使用单条目字段更新 API，仅更新目标字段；不得把 Values 重建为只有 `en-us` 的字典。`SetEntryValue` 传空字符串会删除该语言值，不能用它表示“暂时没有译文”。如确需整表写入，必须由刚读取的完整数据合并本次增量，完成下述保留检查后才写入。
5. **防止覆盖协作修改。** 实际写入前重新读取，核对目标字段未被他人更改。整表写入前必须确认完整数据与备份时一致；发生变化时重新读取并合并，冲突交由用户确认，不能用旧快照覆盖 Team Create 的新内容。
6. **写入前后都核对。** 本次明确修改的英文源文案、英文值和参数示例允许变化；无关条目、已有非英文译文及目标条目的非目标字段必须逐项一致。未获删除授权时，原有条目和语言值不得删除。本次 Key 唯一、源文案非空、参数一致。写入后重新读取实际数据复核，不只看返回成功或总条数。发现意外丢失立即停止后续写入并报告；恢复时先检查期间的协作修改，不盲目整表回滚。

本地文件采用局部编辑并检查 Git diff，禁止通过删文件再生成来维护少量文案。CSV 导入或云端上传前必须确认导入的合并/替换语义；不能把只含修改条目的 CSV 用于覆盖整表。语义无法确认时不执行导入，报告待确认项。删除、清空、语言移除或重建必须有用户明确指定的范围，不能从“整理”“同步”“只保留英文源文案”等模糊要求自行推断。

API 依据：[LocalizationTable](https://create.roblox.com/docs/reference/engine/classes/LocalizationTable)。

## 项目接入与交付要求

当前客户端入口为 `StarterPlayerScripts/Client/Localization.luau`，本地英文兜底来自上述 Studio 表；复用现有调用链。

- 游戏主要面向海外玩家。新增或修改玩家可见文案时，必须使用自然、简洁的英文作为源文案和默认显示，包括 UI、提示、弹窗按钮、物品名称、品质及交互提示；代码注释和开发文档继续使用中文。
- AI 编写代码和维护文案时以英文为准，其他语言由 Roblox 云端自动翻译，并通过项目已有本地化入口按玩家语言展示。AI 不自行编写或更新非英文译文，不新增本地多语言字典、语言分支或自建机器翻译接口；已有非英文译文保留，确需人工修正时由用户在 Roblox 云端翻译门户维护。
- 涉及玩家可见文案时，编码前先定位当前项目已有的翻译入口和英文文案表并复用，不为每个组件创建 Translator 或重复封装。
- 固定 UI 英文文案使用 Roblox 自动本地化，确认显示节点的 `AutoLocalize` 设置；动态数量、物品名称等文案使用稳定 Key 和原生参数模板，例如 `Strength: {value}`、`Loot stored: {count:int}`。禁止先拼接完整句子再翻译；同一条文案不能因数值变化生成不同 Key。
- 服务端业务结果提示由服务端发送 Key 和原始业务参数，客户端按玩家语言格式化；客户端本地交互提示沿用已有本地化入口，不为翻译新增网络请求。需要数量缩写时沿用当前项目已有的统一数值格式化方法，再作为字符串参数传入。译文和格式化字符串不参与计算、存档或发奖。
- 脚本翻译的显示顺序为 Roblox 云端译文 → 本地英文源文案；英文玩家直接显示英文。云端未加载、加载失败、条目或译文缺失时必须保留英文显示，不能让界面空白或显示 Key；本地英文兜底随项目发布，不依赖网络。
- 脚本写入已翻译文本的节点关闭 `AutoLocalize`，避免二次翻译；玩家游戏内切换语言后刷新已显示的动态文案，连接和后台任务按组件生命周期清理。
- 新增或修改 Key 时同步维护英文源文案和参数示例，并检查 Key 唯一、参数名及格式标签一致。动态 Key 需要导入 Roblox 云端翻译表，不能只依赖自动文本采集；交付时明确尚未完成的上传或云端设置，不把本地构建成功当作自动翻译已生效。
- 新增或修改需要本地化的提示、UI 或其他玩家可见文案时，AI 必须通过 Roblox MCP 在 Studio 编辑态维护现有 `game.ReplicatedStorage.Shared.Localization`（`LocalizationTable`，源语言 `en-us`），不要默认要求用户反复导出、修改和导入 CSV。先按上述 MCP 流程确认目标 Studio、编辑态和实例类型，再读取现有条目，新增所需 Key，已有 Key 保持稳定，仅更新本次英文源文案、英文值和参数示例，保留其他条目及已有非英文译文；修改后重新读取并核对结果。
- 本地化表的编辑态读取和写入可使用 Roblox MCP 的 `execute_luau` 调用原生 `LocalizationTable` API；这是文案数据维护，不属于启动试玩或运行游戏测试，不执行业务模块或启动游戏。Script Sync 不同步该表，不能把本地 CSV 或脚本保存成功当作表已更新。MCP 不可用或目标实例无法确认时，明确报告未完成的本地表更新，再说明 CSV 导入的替代步骤。
- 通过 MCP 更新本地 `LocalizationTable` 不会自动更新 Roblox 云端翻译表；交付时分别说明本地表更新及核对结果、云端待上传的 Key 和文案。CSV 用于需要时的云端上传或本地备份，不作为日常 AI 修改本地表的必经步骤。
- 原生 Tool、默认排行榜和图片内文字不能假设自动文本采集会覆盖；按实际显示入口处理。模型名、节点路径、物品 ID 和存档标识保持稳定，不能直接翻译用于代码查找的名称；需要本地化显示名时先将显示文字与业务识别分开。
- 完成涉及文案的代码修改前，检查英文默认显示、动态参数替换及英文兜底；实际试玩仍遵循本工作区的验证授权。仅修改当前任务涉及的文案。
