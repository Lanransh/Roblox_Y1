# Roblox 全表翻译与审查

一次调用持续处理 `translation-upload.csv` 全部条目、全部已有目标语言，包括非空旧译文。先理解每条文案实际用途，再翻译并复核场景；来源摘要、旧译文和机械校验均不能替代语义审查。大表分批续接，不静默缩减范围。

## 输入和边界

- 先读取工作区 AGENTS.md 和 [本地化](../roblox-localization/SKILL.md)。本 skill 是翻译产物维护任务，按用户调用授权修改译文单元格；普通编码任务仍不改翻译产物。
- 当前工程正式文件在 Git 根的 `GameKitWorkspace/Translation/`；旧的 `Scripts/outputs/translations/` 不与新索引混用。其他工程先定位实际导出目录和导出代码。
- 必需输入为同次导出的 `translation-upload.csv`、`translation-ai-context.json`。确认路径、列结构、来源格式；不自行导出覆盖正在审查的表。缺文件时记录阻断。
- 只改已有语言列的单元格；Key、Source、Context、Example、Game Locations、`… translator type` 和其他元数据、表头、行数、顺序不变。索引只读。不新增语言，不排序、去重、改来源或自动上传。
- 用户显式调用 `$roblox-translate`，即授权为理解和验证文案进行必要的 Studio 测试或试玩，同时遵守当前项目及会话的测试边界。授权不等于必须启动游戏；先完成静态调查，仅对仍需运行时证据的具体问题试玩。实现/维护本 skill 本身不构成试玩授权。自动选中 skill 时若没有显式测试授权，先完成静态工作，按现有边界处理必要试玩。

## 开始、分批和续接

按 [脚本用法与记录格式](references/workflow.md) 使用 `scripts/translation_review.py`。仅依赖 Python 3 标准库。

1. `init` 保存输入基线和来源匹配结果，生成独立本地审查 JSON。先 `report` 明确总行数、全部语言、缺译、重复身份、索引问题和已有模板错误。已有记录则续用，不重新初始化丢掉覆盖信息。
2. `batch` 分页读取尚未完成条目及其全部来源和语言；检查记录中的 `glossary`，维护按概念和语言区分的术语及依据，不把不同语义强行统一。
3. 逐条检查所有来源，记录原文核对、用途、参数、显示条件和证据。用途清楚后审查每个语言单元格：补译、修正或保留；再按语言、按功能集中通读关联文案，完成译后复核后设 `reviewed: true`。场景复核可依据充分的静态证据；存在具体运行时疑点时才试玩。复审方法和完成标记要求见流程参考。
4. 不明项保留输入单元格原值（空值仍为空），逐语言写 `pending`：具体疑点、已知证据、阻断原因、所缺信息。共同场景疑点使用行级 `playtest_required`；仅影响某语言的疑点留在该语言的 `pending`/`evidence`，不阻断其他已确认语言。身份歧义未解决前禁止自动应用该条修改。多来源用途冲突时整条待确认，不取第一个来源、不拆 Key。
5. 分批更新同一审查记录，`report`/`batch` 找漏行、漏语言、漏来源及未复核的旧译文。按语言通读可分批，结束前仍须检查全表跨批术语与关联表达，覆盖所有已有语言和旧译文，不以抽样代替。`apply` 先生成候选并检查再替换，保留原始基线统计；可重复应用，下一批在同一记录中继续。冲突或保存失败先检查实际文件和错误，不强制覆盖或重新导出掩盖冲突。
6. 直到整表已处理或其余全部有具体阻断。对可独立处理的条目继续工作，不因某个 MCP、界面或来源失败而结束整表审查。仅因上下文不足不能停工或宣称完成；续接时依记录继续。

## 身份与当前来源

有 Key 按精确 Key 匹配；无 Key 按精确 Source＋Context 匹配。不 trim、改大小写、模糊匹配或合并条目。重复 CSV 身份、重复索引身份、缺失索引、过时索引逐项记录，不能自动取首项。

实际索引是 JSON 数组，每项为 `{key, sources}` 或 `{source, context?, sources}`。`sources` 是 `code:路径:行号`、`node:实例路径.属性`、`config:工作簿路径:工作表!单元格` 字符串。索引按导出行顺序排列，但匹配不能依赖行号。**有 Key 的索引不含 Source 快照**，Key 相同无法证明索引新鲜；必须检查实际定义/节点/配置与 CSV 当前 Source，一致后逐来源填写 `observed_source` 和证据。不同则待确认，不能直接复制旧模板。

## 每条文案的场景调查

- **代码**：沿索引读取定义、实际调用处、参数来源和显示条件。说明功能、界面/状态、按钮/标题/提示等角色；参数是否已经带币种、正负号、单位或格式化数字。不能只读定义行或猜变量名。用限定路径的 `rg` 按需追踪调用。
- **UI 节点**：读取 [Studio 操作](../roblox-studio-operations/SKILL.md)，先通过 Roblox MCP 查询 Edit 模板、周围文案、布局、Text/PlaceholderText、RichText、TextWrapped、尺寸及相关属性。可按界面合并查询，但每条独立结论。静态证据足够时无需启动游戏；需要运行时验证时再核对 Client.PlayerGui 的目标状态。查询到节点、Text、尺寸或坐标不等于界面已打开或文字实际可见。本地代码不能证明节点存在或同步；Generated 和节点均不因翻译表任务修改。
- **配置**：读取 [外部工具协作](../roblox-external-tools/SKILL.md) 的 [XLSX 游戏配置](../roblox-external-tools/references/game-config.md) 参考及相关 MCP 说明，通过配置 MCP 检查源工作表、字段和记录，并追踪消费代码。生成 Lua、ID 或字段名不足以证明用途。只读配置；需要改源文案则待确认。
- **必要试玩**：仅在静态证据无法解决具体用途、参数或显示问题时进行。启动前明确受影响条目、疑点、静态证据为何不足、目标界面/状态、打开/触发方式及预期核验内容，记录方式见流程参考。打开方式尚未找到时先继续定位。随后用 Roblox MCP 打开界面、触发状态，确认目标可见、条件成立并观察结果；仅启动游戏、读取隐藏节点或查询按钮位置均不算完成试玩。MCP 不可用、入口无法定位、状态无法触发或缺额外权限时，记录具体问题并继续其他条目。禁止为观察文案修改存档、支付或进行无关操作。

## 翻译与模板

- 每个目标语言均补空并审查已有值；当前 Source 和实际场景是依据。动作、对象、条件、数量、奖励、参数含义准确，按钮简洁，语法、词序、标点符合各语言习惯。
- 按语言将同一功能的按钮、状态、提示和引导连起来读，检查动作表达、状态区别、数量对象和游戏术语，避免逐词直译。动态参数须结合实际取值范围代入，检查助词、词尾、单复数、性别、冠词和量词；无法可靠处理变化时采用不依赖该变化的自然句式，不改参数契约。
- 发现术语漂移时检索整表该概念的关联用法，复查按钮、状态、提示及相关地区语言列，各地区分别判断。显示空间可依据布局证据复核；仍有裁切、遮挡等具体疑点时按必要试玩流程核验。
- 用共享术语记录保持同概念一致；结合具体 UI 调整长度、换行，不能为缩短删除含义。换行必须是真实换行，不写成字面 `\n`。调整后复核显示空间；脚本不判断语义、排版或应否换行。
- 完整保留参数名、大小写、格式和次数；允许移动。`{level:int}` 不能变成 `{level}`。纯参数 Source 原样保留；不得给 `{price}` 等添加 `+$`、单位或重复格式化。
- 保留富文本配对、嵌套、标签及必要属性值，可按语序移动包裹位置；仍需检查包裹的对象是否正确。支持语法和无法机械确认的边界见脚本参考；校验通过不代表显示含义正确。
- 任何语言意思仍不明确，保留其原值并设待确认；不用占位说明或另一种猜测覆盖旧值。来源不足时不把格式正确的旧译文标为语义完成。

## 交付

运行全表 `report`，应用后再 `report` 核对实际落盘值。报告必须包括：

- 文案总条目、来源总数和已检查数；目标语言列表，应审查与已完成语义审查单元格数。
- 相对最初输入的补译、修正、保留、待确认数；另列未审查数，不把漏处理合并到成功状态。每单元格仅计一次，与修改轮数无关。
- CSV 结构及非译文列不变的检查结果，占位符/富文本/缺译失败数和具体清单（含未修改旧译文）。身份和来源匹配问题分别报告。
- 各语言集中复审的功能、条目覆盖及跨批术语检查结果；来源核实、语言复审和模板校验分别报告，不相互替代。
- 实际试玩界面/状态、操作、观察及未验证范围。区分原界面/已有云端译文、候选文字尺寸测量、候选译文实际显示；报告语言、条目和译文版本，不将其中一种当成另一种验证。待确认项列明身份、疑点、已知证据和所缺信息。
- CSV 和审查记录的绝对路径；明确云端尚未上传。若校验/保存失败，明确原文件未替换及尚未应用的修改。

仅整表全部语言完成语义复核、全部来源已检查、必要验证通过、无缺译/待确认/未处理和校验错误，且结果已落盘时，才报告全部完成。其余准确报告完成范围和剩余数量。
