范围约定：这里的“转圈”解释为模型绕自身竖直轴旋转，不是绕掉落位置公转；“一点点漂浮”解释为小幅、平滑的上下往复。效果作用于已揭露的场景战利品，普通与幸运掉落都包含，不扩展到背包图标、手持道具或基地收藏品。

## 2. 目标表现

1. 战利品出现后保留现有短暂弹出过程，随后进入发光、旋转和漂浮的待拾取状态。
2. 以战利品为中心向四周铺开放射光芒，形成与拾取 UI 背景相近的光环。模型保持清晰，光芒外缘渐隐，不用强光把模型涂成一团白色。
3. 模型在固定位置缓慢自转，不发生横向位移、不倾倒、不绕圈移动。
4. 漂浮在固定高度附近平滑往复，到最高点和最低点自然减速，不抖动、不突然跳回起点。最低位置不能穿入地面。
5. 名称、品质、价格、倒计时保持可读；拾取提示继续可用，文字不随模型旋转。
6. 拾取成功、到期消失、回基地清理或组件销毁时，光效和运动一起结束。满包等拾取失败时，继续保持待拾取表现。
7. 掉落归属、价格、幸运倍率、生命周期和发奖规则沿用现有逻辑。

- `StarterPlayerScripts/Client/Player/CRockLevelCompClass.luau` 已有客户端更新入口及掉落 HUD 倒计时逻辑，可作为表现接入位置。

## 4. 建议实现

### 4.1 职责与生命周期

服务端继续保存真实掉落、固定拾取位置、有效期和奖励状态。持续视觉动画放在项目客户端组件中，避免每帧由服务器复制模型运动。

保留服务端现有弹出阶段；结束后停止现有无限漂浮 Tween，让服务端模型停在最终落点。此时记录最终落点基准和表现开始时间，并开放拾取，客户端再开始旋转与轻微漂浮。不要同时保留两个持续写 CFrame 的动画。

客户端只对服务端已创建的有效掉落添加表现，不根据石头击破预测奖励。初次进入、复制延迟和流式加载后，都按掉落属性补注册；节点移除时注销。注册时等待本掉落必需属性和 PrimaryPart 齐全，不把未复制完整的模型当成无效奖励。

本方案优先在客户端移动已复制掉落的视觉姿态，服务端仍以固定落点判定距离；实施时必须确认锚定装配的本地移动不会被服务端更新反复覆盖。若确有覆盖问题，再采用客户端展示副本，届时明确处理原模型隐藏、HUD 和提示绑定，不能让玩家看到两个模型。

### 4.2 自转与漂浮

用同一更新入口计算并一次性设置模型姿态，不分别创建“旋转 Tween”和“漂浮 Tween”争抢 CFrame。

- 以最终落点建立不可变基准，每帧从基准计算，避免累加位置造成漂移。
- 用经过时间计算旋转角度：角度 = 角速度 × 时间。
- 用正弦曲线计算上下偏移：偏移 = 振幅 × sin(2π × 时间 / 周期)。
- 绕模型视觉中心的世界竖直轴旋转，保留模型原始朝向；PrimaryPart 偏离模型中心时，保存中心到模型 Pivot 的固定变换，避免偏心公转。
- 首次进入待拾取状态时，通过短暂平滑过渡衔接弹出落点，避免切换到漂浮中心时跳动。
- 根据模型高度和地面高度确定漂浮中心，保证最低点留有间隙。
- 使用一个共享帧更新连接遍历已登记掉落，不为每件战利品建立无限循环，也不每帧扫描整个 Workspace。

建议初始调试参数：

| 参数 | 建议值 | 含义 |
| --- | --- | --- |
| 自转速度 | 45°/秒 | 约 8 秒转一圈 |
| 漂浮振幅 | 0.15 stud | 中心上下各 0.15，总行程 0.3 stud |
| 漂浮周期 | 2.6 秒 | 一次完整上下往复 |
| 最低点离地间隙 | 至少 0.2 stud | 按模型包围盒校正 |

这些数值用于第一次调试；现有 0.8 stud 单向漂浮应被新方案替换，不能叠加。不同大小模型需要现场确认观感，不新增掉落数值玩法。

### 4.3 发光

光效按已明确的“向四周散开、接近拾取 UI 背景”实现。优先在客户端为战利品增加独立的 BillboardGui 光环层，复用 `ShowPickupEffect` 中 12 条放射射线、浅金色和透明度渐变的构造方式，不修改现有拾取 UI。

- 光环中心对齐模型视觉中心，始终面向相机，从中心向四周放射，外缘透明渐隐。这里的“四周散开”是放射形态，不额外要求粒子持续向外飞散。
- 建议光环直径约为模型可见尺寸的 1.5～1.8 倍，沿用拾取 UI 的浅金色作为初始样式，实际大小和透明度现场调整。
- 光环跟随战利品上下漂浮，可沿用拾取 UI 的缓慢旋转观感；模型绕世界竖直轴自转与光环在画面平面内旋转分别计算，不让名称等 HUD 一起转动。
- 设置 `AlwaysOnTop = false`，不形成隔墙可见提示；现场验证光环射线不会覆盖模型主体或 HUD。BillboardGui 与世界模型的遮挡不由 GUI 的 ZIndex 保证，若有覆盖，先扩大中心留空范围并调整深度位置。
- 此方案用原生 UI 图形即可制作，不需要新增贴图或上传资产，不以 PointLight、Highlight 或全局 Bloom 代替放射光环。
- 光环持续存在于待拾取阶段，拾取、到期或清理后销毁；不照搬拾取 UI 的 1.3 秒后飞向背包生命周期。

若后续确需制作非脚本特效模型，资源模板在 Studio 中维护，存放于 `ReplicatedStorage.Assets.Decorations`，不放入任何 `BlockMeshs` 容器。本方案目前不要求新增此模板。

### 4.4 HUD、拾取与清理

- HUD 继续使用 BillboardGui，使文字面向相机；检查当前世界空间偏移在旋转、漂浮后仍位于模型上方。
- 原生 ProximityPrompt 保留，拾取距离与奖励验证仍由服务端负责。客户端视觉偏移只改变外观，不能改变权威奖励位置。
- 成功拾取或到期后，以服务端移除为准注销动画与光效；不由客户端动画完成决定发奖。
- 节点暂时流出再流入时重新绑定；掉落已过期则不重新启用表现。
- 组件销毁时断开更新和监听，清理客户端创建的光效。失败拾取不提前清理。
