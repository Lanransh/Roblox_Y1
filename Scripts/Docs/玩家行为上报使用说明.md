# 玩家行为上报使用说明

实施日期：2026-10-19。代码已接入，运行与正式后台验收尚未完成。

## 开关与数据范围

在源配置表 `GameConfig.xlsx` 的 `CommonConfig` 页签维护：`AnalyticsEnabled` 控制正式发送，`AnalyticsExcludedUserIds` 填额外排除账号的数字 UserId，多个账号用英文逗号分隔，当前为 `2563885143`。保存并通过配置工具导出到 `ReplicatedStorage/Scripts/Game/Configs/GameConfig.luau` 后，统计代码读取 `GameConfig.CommonConfig` 中的对应字段，不直接编辑生成文件。`ReplicatedStorage/Scripts/GameInit.luau` 中 `FX.IsDeveloper` 判定的开发账号始终排除；Studio 由框架统一禁止真实发送。排除上报不删除玩家存档，也不停止在线计时。

本系统面向首次发布的新档，不迁移历史测试档，不补发历史消费。会话从项目登录完成开始，包含挂机；`TrainingPlaytime` 每秒按实际经过时间增量记账，在首付及正常离服补齐尾差，沿用原自动保存和离服保存。

## Creator Hub 查看方式

进入 [Creator Hub](https://create.roblox.com/dashboard/creations) → Creations → 选择游戏 → Analytics。按后台语言查找以下报表：

| 问题 | 报表与查看方法 |
| --- | --- |
| 新手停在哪一步 | Funnels → Onboarding，查看步骤转化与流失；第 9 步为全部完成 |
| 首局离开阶段和在线时长 | Custom Events → `SessionEndedDuration`，按字段 1 阶段及字段 2 会话类别筛选，查看事件数与平均 value |
| 首局与回访人数 | Custom Events → `SessionStarted`，按字段 2 区分；事件数为会话数，独立人数为玩家数 |
| 买了哪个光环、镐子 | Economy → Sinks，选择 Money，按 SKU 查看次数、独立人数及消耗金额 |
| 钻石买了什么、多少包、花多少 | Economy → Sinks，选择 Diamonds，按 `GemGoods:<ID>` 查看交易次数和总金额；一次交易为一个商品包 |
| Robux 消费、首付商品及首付前时长 | Custom Events → `RobuxPurchase` / `FirstPurchasePlaytime`，按商品及首付分类筛选 |

发布环境先用相应报表的 **View Events** 核对近期事件，再等待约 24 小时生成聚合图表。Studio 无法验证后台入库。后台权限、菜单可见性和 Roblox 的数据量要求以当前 Creator Hub 为准。真实收入、留存及整体参与时长继续使用 Roblox 原生 Monetization / Retention / Engagement 报表。

## 固定事件与字段

字段 1/2/3 对应官方 `CustomField01/02/03`，均为字符串；金额、时长使用原始数值。

| 事件 | value / 金额 | 字段 1 | 字段 2 | 字段 3 |
| --- | --- | --- | --- | --- |
| Onboarding | 到达步骤 1–9 | `FirstLootV1` | 未使用 | 未使用 |
| `SessionStarted` | 1 | `FirstLootV1` | `FirstSession` / `ReturningSession` | `V1` |
| `SessionEndedDuration` | 本次在线秒数 | `NotStarted` / `Step1`…`Step8` / `Completed` | `FirstSession` / `ReturningSession` | `V1` |
| Economy Sink | 实际扣款，余额为本笔结算后余额 | 未使用 | 未使用 | 未使用 |
| `RobuxPurchase` | 官方 `receipt.CurrencySpent`，实际 Robux 支出 | 业务 `DevGoodsId` | `AddGem` / `AddItem` / `SkipRebirth` | `FirstPurchase` / `RepeatPurchase` |
| `FirstPurchasePlaytime` | 首次结算时累计在线秒数 | 业务 `DevGoodsId` | `OnlineSinceFirstLogin` | `V1` |

主引导稳定步骤名：

| 步骤 | 报表名 | 含义 |
| --- | --- | --- |
| 1 | `CollectTwoItems` | 到达收集步骤 |
| 2 | `DepositLoot` | 到达回基地入库步骤 |
| 3 | `SellLoot` | 到达出售步骤 |
| 4 | `BuyTrainingRate` | 到达购买倍率步骤 |
| 5 | `EquipStrongerWeapon` | 到达装备更强镐子步骤 |
| 6 | `TimedTrainingReminder` | 训练说明计时提醒 |
| 7 | `TimedEncouragement` | 鼓励计时提醒 |
| 8 | `TimedRewardReminder` | 奖励入口计时提醒 |
| 9 | `Completed` | 前 8 步全部完成 |

步骤表示“当前到达”，不表示完成该步骤。6–8 为系统提醒，不能当作主动操作。光环独立引导不并入主漏斗。重登只续接同一个平台一次性漏斗；同一会话不会因重复状态提交重复发送步骤。

| Robux 100 / 101 / 102 / 103 | Robux | 分别到账 48 / 152 / 618 / 1698 钻石；每次一包 | 官方新收据发奖且档案保存成功之后 |
| Robux 111 / 112 | Robux | 对应 101 / 102 道具各一张；使用时才激活周卡 | 同上 |

以上为实施时映射，后续新增或调整商品需同步核对配置与文档；运行金额始终读取服务端配置与真实收据，不使用本表作为结算依据。当前支持的 Robux 商品 `RobloxProductId` 尚为空，需通过原 XLSX 配置流程填写有效平台产品 ID 后才能进行对应真实购买验收。配置中的 VIP、红包等未接入处理器不属于本次新增上报范围。

所有钻石扣费入口已按服务端 Diamonds 引用和奖励成本调用审查，本次覆盖钻石商店三类商品；福利、卡片和礼盒属于钻石来源，不额外上报。失败、重复 Buy、装备/卸下、免费赠送及零成本解锁不产生 Sink。本版仅观察这些商店消费，不构成完整经济收支表。力量包购买次数代表包数，不代表实际训练值数量；实际训练值随玩家状态变化，本版不另报训练值收益事件。

## 支付去重及准确性边界

- `PurchaseReceipts[PurchaseId]` 为奖励与分析的同一权威记录，新记录保存分析快照和“已安排尝试”标记。捕获新交易时，没有既有收据即为首付，不再增加独立的已付费布尔值。
- 新收据发奖时捕获商品、实际 Robux、首付分类和累计在线；保存失败时，内存保留同一快照，后续同笔保存成功才尝试上报。历史已确认收据不会再次上报。
- 项目登录未完成时返回 NotProcessedYet，等待平台重试。保存完成后仍检查原玩家对象、档案会话及离服状态，避免向重进会话发送旧交易结果。
- 分析副作用在购买串行锁释放前使用保存前的快照；异常不改变奖励、保存结果或支付决定。上报失败不重试、不额外存档。框架平台调用整服最多输出五次失败诊断。
- 第一笔“首次付费”定义为本系统首次结算的购买。官方收据没有付款时间，不还原多个待处理收据的真实付款先后。
- DataStore 与 AnalyticsService 无原子提交；先持久化再发送，进程退出或平台调用失败可能漏报，接受漏报以避免重报。正常离服尾差会保存；进程崩溃可能丢失尚未持久化的在线增量和离服事件。首局标记同样受存档成功与否影响。
