## 开关与数据范围

在源配置表 `GameConfig.xlsx` 的 `CommonConfig` 页签维护：`AnalyticsEnabled` 控制正式发送，`AnalyticsExcludedUserIds` 填额外排除账号的数字 UserId，多个账号用英文逗号分隔，当前为 `2563885143`。保存并通过配置工具导出到 `ReplicatedStorage/Scripts/Game/Configs/GameConfig.luau` 后，统计代码读取 `GameConfig.CommonConfig` 中的对应字段，不直接编辑生成文件。`ReplicatedStorage/Scripts/GameInit.luau` 中 `FX.IsDeveloper` 判定的开发账号始终排除；Studio 由框架统一禁止真实发送。排除上报不删除玩家存档，也不停止在线计时。

本系统面向首次发布的新档，不迁移历史测试档，不补发历史消费。会话从项目登录完成开始，包含挂机；`TrainingPlaytime` 每秒按实际经过时间增量记账，在首付及正常离服补齐尾差，沿用原自动保存和离服保存。

## Creator Hub 查看方式

进入 [Creator Hub](https://create.roblox.com/dashboard/creations) → Creations → 选择游戏 → Analytics。按后台语言查找以下报表：

| 问题 | 报表与查看方法 |
| --- | --- |
| 新手停在哪一步 | Funnels → `FirstLootV2`，查看实际动作完成转化；共 7 步 |
| 新手后的成长流失 | Funnels → `GrowthV1`，查看引导完成、首次重生、世界 2/3 解锁 |
| Robux 商店购买转化 | Funnels → `RobuxPurchaseV1`，按字段 1 的进店钻石余额区间筛选 |
| 购买各阶段的钻石余额 | Custom Events / Explore → `RobuxPurchaseDiamonds`，按字段 1 阶段分组，查看平均 value |
| 买了哪个光环、镐子 | Economy → Sinks，选择 Money，按 SKU 查看次数、独立人数及消耗金额 |
| 钻石买了什么、多少包、花多少 | Economy → Sinks，选择 Diamonds，按 `GemGoods:<ID>` 查看交易次数和总金额；一次交易为一个商品包 |
| 首付商品及首付前时长 | Custom Events → `FirstPurchasePlaytime`，按商品筛选，查看平均 value |

发布环境先用相应报表的 **View Events** 核对近期事件，再等待约 24 小时生成聚合图表。Studio 无法验证后台入库。后台权限、菜单可见性和 Roblox 的数据量要求以当前 Creator Hub 为准。真实收入、留存及整体参与时长继续使用 Roblox 原生 Monetization / Retention / Engagement 报表。

主引导稳定步骤名：

| 步骤 | 报表名 | 含义 |
| --- | --- | --- |
| 1 | `GuideStarted` | 已开始新手引导 |
| 2 | `TwoItemsCollected` | 两件物品收集完成，引导进入入库步骤 |
| 3 | `LootDeposited` | 入库完成，引导进入出售步骤 |
| 4 | `LootSold` | 出售结算完成，引导进入倍率购买步骤 |
| 5 | `TrainingRatePurchased` | 倍率升级已生效，引导进入装备步骤 |
| 6 | `StrongerWeaponEquipped` | 已装备更强镐子，引导进入末尾提醒 |
| 7 | `GuideFinished` | 末尾提醒展示结束，引导状态为 Finished；不代表实际领取奖励 |

新版使用独立通用漏斗 `FirstLootV2`，固定会话标识 `LifetimeV2`，不再向旧 Onboarding 的 1–9 步发送事件。第 2–6 步由服务端权威引导进入下一步确认上一动作完成；三段计时提醒合并为引导结束点，不再各占一根柱子。实际领奖不属于本漏斗，光环独立引导也不并入。

`FirstLootV2Step` 私有持久字段记录已尝试上报的最高步骤。只有第 1 步可以建立流程，重复状态提交和正常重登不重报；未记录开始点的旧测试档不会登录补报后半段，不做旧存档迁移。测试新版完整流程需使用从第一步开始的测试档。新手统计的最后一步只表示引导结束，不表示完成领奖。平台调用失败或保存前进程退出仍可能漏报或重试，不提供逐事件送达保证。

## 成长与购买漏斗

成长漏斗 `GrowthV1` 的顺序为 `GuideCompleted` → `FirstRebirth` → `World2Unlocked` → `World3Unlocked`。首次重生按 RebirthCount 大于零判断；世界解锁使用 MaxTrainingLevel 与 WorldTransferConfig 的门槛比较，当前为 195 / 390，不要求实际传送。登录恢复最高已到达里程碑，训练和重生进度变化时继续推进；使用固定 `LifetimeV1` 漏斗会话标识，跨进服续接。后续步骤自动计入前序完成；平台超过 180 天无事件会过期，不能当作永久存档。

购买漏斗 `RobuxPurchaseV1` 的顺序为 `ShopOpened` → `ProductSelected` → `PromptRequested` → `PurchaseGranted`。只覆盖货币商店 Robux 页，不把跳过重生等其他入口算作商店访问。切到 Robux 页或重新打开该页时开始曝光；同一页内再次购买会建立新的流程并记录一次曝光。同一流程同一步只发送一次，Open / Select 分别最多每秒接受一次。

每个购买流程使用服务端生成的 GUID，仅放在官方 funnelSessionId，不作为自定义字段。第一步固定进店钻石区间：`0`、`1-49`、`50-199`、`200+`；分组沿用第一步值。精确余额在各阶段通过 `RobuxPurchaseDiamonds` 的 value 发送，不嵌入步骤名或作为高基数字段；进店尚未选商品，商品字段为 `None`。购买成功余额取发奖后、保存前的快照，可能包含本次购买获得的钻石。

第三步表示预检成功且 PromptProductPurchase 调用返回，不代表客户端屏幕已确认显示支付窗口。取消、预检拒绝或调用异常不发送成功步骤。第四步只由收据发奖及保存成功触发，复用现有收据去重与失败重试快照；客户端不能提交成功步骤或余额。

每次点击携带独立 attemptId，仅用于匹配选择、弹窗请求和取消动作；客户端取消必须匹配服务端保留流程的 attemptId，后续同商品重试失败或取消不会删除上一笔等待收据的流程。attemptId 不用于收据关联，也不作为分析字段。

官方收据没有本项目的购买流程 ID，因此仅按同一玩家会话中的产品 ID 关联。上一笔同商品尚未捕获收据时，新的同商品选择不覆盖原流程；统计不阻止玩家购买。跨服补发、历史待处理收据或其他入口的购买无法保证与当前点击一一对应，这类统计不是支付账本。没有流程的成功收据只记录 `Unattributed` 余额事件，不新建已完成漏斗；旧快照缺少新增字段时继续保留首付时长上报。

## 支付去重及准确性边界

- `PurchaseReceipts[PurchaseId]` 为奖励与分析的同一权威记录，新记录保存分析快照和“已安排尝试”标记。捕获新交易时，没有既有收据即为首付，不再增加独立的已付费布尔值。
- 新收据发奖时捕获商品、首付标记和累计在线；保存失败时，内存保留同一快照，后续同笔保存成功才尝试上报首付累计在线。非首付及历史已确认收据不会上报。
- 项目登录未完成时返回 NotProcessedYet，等待平台重试。保存完成后仍检查原玩家对象、档案会话及离服状态，避免向重进会话发送旧交易结果。
- 分析副作用在购买串行锁释放前使用保存前的快照；异常不改变奖励、保存结果或支付决定。上报失败不重试、不额外存档。框架平台调用整服最多输出五次失败诊断。
- 第一笔“首次付费”定义为本系统首次结算的购买。官方收据没有付款时间，不还原多个待处理收据的真实付款先后。
- DataStore 与 AnalyticsService 无原子提交；先持久化再发送，进程退出或平台调用失败可能漏报，接受漏报以避免重报。正常离服尾差会保存；进程崩溃可能丢失尚未持久化的在线增量。
