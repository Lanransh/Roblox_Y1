# UI 编辑器项目计划

更新时间：2026-10-06

项目名称：UI 编辑器（内部使用）

当前状态：需求与实施计划阶段，尚未开始实现。

## 1. 项目目标

开发一个独立 App，用节点、模板和 AI 制作 Roblox 游戏 UI。支持编辑布局和样式，并用模拟数据预览状态变化。界面定义导入 Roblox 后，由提前编写的展示代码创建和更新界面，游戏业务提供数据并处理用户操作。

首个验证界面为在线奖励界面：侧边导航、标题栏、奖励卡片、倒计时、领取按钮和锁定状态。先跑通一个完整界面，再扩展模板与 AI 能力。

## 2. 已确认方向与工作假设

### 已确认

- 独立 App，内部名称为「UI 编辑器」。
- 提供基础节点和模板节点，支持 AI 生成界面。
- 界面与业务逻辑分离，展示代码提前编写。
- App 编辑并导出界面数据，Roblox 接入业务数据与动作处理。
- Stud 效果使用小图片平铺，不逐个创建凸点节点。
- 动态界面预览是核心需求，包含数据更新和状态切换。

### 用于拆分计划的假设

- 首版面向 Roblox 的二维屏幕 UI。
- 首版采用文件导出和 Studio 插件导入，暂不做实时同步。
- App 不执行任意业务脚本；动态展示使用受限的数据绑定、状态和动作定义。
- 技术栈、AI 接入方式和模板数量尚未确定，不在本计划中预先锁定。

## 3. 首版范围

### 包含

- 基础节点：面板、文字、图片、按钮、列表容器。
- 布局属性：位置、尺寸、锚点、层级及父子关系；支持明确映射到 Roblox 的 Scale/Offset。
- 样式属性：颜色、透明度、圆角、描边、基础渐变、Stud 平铺和九宫格图片。
- 画布选择、拖动、缩放、节点树和属性面板。
- 保存、加载及基本撤销重做。
- 模板实例的内容和样式覆盖。
- 数据绑定、组件状态、列表生成和点击动作。
- 模拟数据编辑与交互预览。
- AI 根据需求组合已有节点和模板，生成可继续编辑的界面定义。
- Roblox 通用展示代码及 Studio 导入插件。

### 暂不包含

- 通用脚本编程、真实发奖、支付和存档逻辑。
- 多人协作、模板市场和其他引擎导出。
- 对 Figma 或 Roblox Studio 全部能力的复刻。
- 复杂动画时间轴和自动上传图片资源；首版先填写已上传的 Roblox 资源 ID。

## 4. 数据与职责划分

流程：需求描述 → AI 组合节点和模板 → App 编辑与动态预览 → 导出界面定义 → Studio 导入 → Roblox 接入业务数据与动作。

| 部分 | 内容 | 负责方 |
| --- | --- | --- |
| 界面定义 | 节点、布局、样式、模板引用、状态、绑定、动作声明 | App |
| 资源映射 | App 预览图片与 Roblox 资源 ID 的对应关系 | App 导出与导入插件 |
| 展示实现 | 节点创建、数据更新、状态展示、事件连接与清理 | Roblox UI 运行库 |
| 业务数据 | 奖励名称、图标、剩余时间、奖励状态 | 游戏业务 |
| 业务动作 | 接收领取意图、校验资格、发奖并返回结果 | 游戏业务与服务端 |

界面数据不决定奖励是否可领取，也不作为发奖依据。展示层只发送动作名与必要业务标识，业务完成后更新数据驱动界面。

导入节点与业务接入代码分开保存，使用稳定节点 ID 和动作名建立关联，避免再次导入时覆盖业务代码。

### 首个奖励卡片的绑定契约

| 数据或动作 | 用途 |
| --- | --- |
| `id` | 奖励的稳定业务标识 |
| `rewardName` | 奖励显示名称 |
| `rewardIcon` | 奖励图片资源 |
| `remainingSeconds` | 剩余秒数，由展示层格式化为时间 |
| `status` | `Locked`、`Claimable`、`Claimed` |
| `claimReward` | 点击领取时发出的动作，携带奖励 ID |

数量、时间等绑定保留原始数据，通过预定义格式化方式显示。界面定义不保存需要执行的任意表达式。

## 5. 实施阶段与验收

### 阶段一：确定数据契约并验证 Roblox 展示

目的：先确认数据能生成目标界面，降低后续 App 与 Roblox 不一致的风险。

- [ ] 确定独立 App 项目的目录与技术栈；本文件只是当前游戏项目中的规划文件。
- [ ] 明确界面定义格式、版本号、稳定节点 ID、支持属性及单位。
- [ ] 明确绑定、状态、列表和动作的最小数据结构。
- [ ] 明确模板引用与实例覆盖的规则，不做任意继承体系。
- [ ] 明确图片平铺、九宫格、资源 ID 和预览图片的映射。
- [ ] 选择文字与字体支持范围，明确 App 与 Roblox 的预览差异。
- [ ] 手工准备在线奖励界面的最小界面定义。
- [ ] 实现首批 Roblox 展示组件，验证定义、数据和动作接口。

验收：同一份定义能在 Roblox 中展示奖励界面；修改输入数据能更新倒计时和三种奖励状态；点击领取能传出正确动作与奖励 ID。

### 阶段二：App 基础编辑能力

- [ ] 创建画布、节点树和属性面板。
- [ ] 支持基础节点的创建、删除、复制和父子关系调整。
- [ ] 支持选择、拖动与尺寸调整，并同步修改界面定义。
- [ ] 支持圆角、描边、渐变、图片平铺和九宫格设置。
- [ ] 支持界面文件保存、加载和基本撤销重做。
- [ ] 支持桌面与手机尺寸预览，检查文字换行和列表布局。

验收：无需手工改界面数据，能在 App 中编辑首个奖励界面；保存再打开后结构与属性一致；撤销重做覆盖基本编辑操作。

### 阶段三：模板与动态预览

- [ ] 制作 Stud 按钮、奖励卡片、弹窗和侧边导航模板。
- [ ] 配置模板实例的名称、图片、颜色和绑定。
- [ ] 提供模拟数据面板，修改数据后刷新预览。
- [ ] 支持 `Locked / Claimable / Claimed` 状态的属性切换。
- [ ] 支持列表通过数据生成重复项，以稳定业务 ID 区分条目。
- [ ] 提供预览模式，演示导航切换和领取后的状态变化。
- [ ] 检查长文字、空列表和奖励数量变化时的布局。

验收：同一张卡片切换三种状态，无需复制三套界面；编辑模拟数据能更新文字和列表；预览动作不会修改真实游戏数据。

### 阶段四：导出与 Studio 导入

- [ ] 确定导出格式，并提供明确的版本与结构校验。
- [ ] 制作 Studio 导入插件，调用既有展示组件生成原生 UI。
- [ ] 检查导入后的父子结构、节点属性、资源及数据绑定。
- [ ] 再次导入时只更新插件管理的界面范围，并报告资源缺失或不支持的属性。
- [ ] 用稳定标识保留业务接入关系，避免依赖显示文字查找节点。
- [ ] 接入当前游戏框架时使用项目 UI 子类，不直接修改 FC 框架代码。
- [ ] 接入现有英文文案与本地化入口；固定文案及动态参数遵循当前项目规则。
- [ ] 对比 App 与 Roblox 中的尺寸、文字、边缘、Stud 密度和状态展示。

验收：首个奖励界面能完整导入；再次导入不覆盖业务代码、不重复绑定事件；未完成的资源和云端本地化设置有明确提示。

### 阶段五：AI 生成界面

依赖：节点格式、模板和导入链路已经稳定。

- [ ] 确定 AI 接入方式与凭据保存方式。
- [ ] 向 AI 提供已有节点、模板、属性和绑定契约。
- [ ] 支持由自然语言需求生成结构化界面定义。
- [ ] 校验节点类型、属性、引用、绑定和动作声明后再加载预览。
- [ ] AI 生成的结果能够继续由画布和属性面板编辑。
- [ ] 用「四张在线奖励卡，第一张可领取，其余锁定」验证完整链路。

验收：AI 生成的奖励界面无需手工修改数据格式即可打开、编辑和导入；不支持的内容得到清晰反馈；已有模板风格保持一致。

### 阶段六：首版交付验证

- [ ] 用独立 App 完成在线奖励界面的制作与导出。
- [ ] 游戏业务接入真实数据和领取动作，界面展示保持独立。
- [ ] 按实际设备检查视觉一致性和操作体验。
- [ ] 检查重复打开、关闭和刷新界面的节点与事件清理。
- [ ] 在代表性手机设备上记录 UI 性能，比较复用 Stud 小图的资源和绘制开销。
- [ ] 编写最短使用说明：创建界面、绑定数据、预览、导出、导入和业务接入。

验收：首个界面的制作、动态预览、导出、导入与业务接入全部可重复完成，并记录实际验证结果。

## 6. 验证边界

- 本计划的复选框表示待办，不代表当前已经实现或测试通过。
- App 的模拟预览不能作为 Roblox 实际显示和性能已验证的证据。
- 在当前 Roblox 工作区新增或修改 Luau 后，默认只做编译/语法验证、相关 Rojo 构建及 diff 检查。
- 实际运行、试玩和设备测试列为后续验收任务，执行时需要用户明确授权。
- 本阶段只新增计划文件，不修改游戏代码、UI 资源或现有功能验收清单。

## 7. 下一步

先确定 App 项目位置与技术栈，再完成阶段一的数据契约和奖励界面样例。以「同一份界面定义能准确展示并被数据驱动」作为第一次实现的成功标准。
