# 项目本地化

编码智能体使用 [Roblox 项目本地化 skill](../.agents/skills/roblox-localization/SKILL.md)。
本文规定游戏动态文本的最小接入范围：先检查 Generated，只对其尚未正确处理的
动态文本在接入脚本补翻译；无 Generated 对应的业务动态消息由所属脚本处理。
Generated 不直接修改，静态节点与配置翻译由工具处理。

## 文案定义与收集

业务动态文案采用分散同名静态表，每个文件最多一个顶层声明。这里的“静态表”
指可被工具解析的字面量结构，不表示需要把 UI 静态文字登记进来：

```lua
local TranslationTexts = {
    Count = { Key = "Inventory.Count", Source = "You have {count:int} items" },
}
```

Key 为全局唯一语义身份，Source 为英文原文或完整模板；每项只允许这两个非空
字符串字面量。表保持只读，不动态拼接、补项或重新赋值。每个 Luau 只在本文件
定义自己负责的动态文案，不创建全局/集中共享表，不导入或导出文案表；手写 UI 中
属于业务的动态消息同样遵守，
生成 UI 跳过。同一句在不同文件使用时分别声明，用文件模块前缀 Key 保证全局唯一。
完整静态约束与接入步骤以[本地化 skill](../.agents/skills/roblox-localization/SKILL.md)为准。

新增或修改脚本文案不再通过 Text.Tr/Text.Mark 的调用字面量定义或登记。
工具按“编辑态节点 → 脚本 TranslationTexts → 勾选 XLSX 字段”三路收集；
表项即使未调用也会收集。配置保持普通字符串、Key=Source，不手改生成脚本。

## 代码与工具的职责

先读取 Generated 展示类的 Render、文本赋值和翻译逻辑，不修改生成脚本。
已正确处理的动态文本不重复翻译；只有确认它未处理好的动态文本，才在手写接入
脚本中最小补充。进度或状态会变化本身不代表需要补翻译，仍需核对生成类实际行为。
没有 Generated 对应的奖励、交互结果等业务动态消息，由产生或显示它的脚本处理。

每个文件独立定义自己需要的动态文案，不创建全局共享表；Key 在收集范围内不能
重复，原文相同也不例外。同文件复用已有项，跨文件用各自模块前缀区分。
配置引用由工具处理，不复制字段到文案表或补 Key/Source 定义、翻译兼容层。
固定标题、按钮文字、说明等静态节点文本由工具收集，不在业务组件补翻译表或覆盖；
即使通过脚本赋值，也不因此纳入动态文本改造。生成配置与静态节点均不修改。

当前生成展示类仍用英文拼接等级、数量、价格等运行数据，接入层保留这些模板的动态
翻译补充及业务状态提示；固定标题、固定说明、静态按钮/页签不再登记定义或重复覆盖。
收藏品与道具名直接读取配置，通过 Text.TrSource 查询已有译文，不按模型编号另外复制名称表。
任务描述和商店的配置说明同样直接读取配置、按原文查询；只有计算实时容量等业务模板保留参数定义。
已经翻译的动态描述关闭二次翻译，购买确认沿用同一约定。

仅对业务实际负责翻译的具体动态节点，在客户端运行时设置 AutoLocalize=false；
不修改 Studio 模板、导入数据或整个界面的本地化属性。

## 运行时合同与迁移状态

新定义要求客户端按 `Translator:FormatByKey(definition.Key, arguments)` 查询，
失败按 definition.Source 格式化英文，不按 Source 串用其他 Key 的译文。
服务端发送 Key、Source 和独立参数，不翻译。语言变化后用定义及参数重新求值，
连接随组件清理；提示刷新不重置计时。

Text.Tr 已接受 Key/Source 定义并校验两个非空字符串。Localization:Tr 的定义分支
不受本地旧 Key 表限制，只查询该语义 Key；云端不可用、查询报错或返回空串时，
用独立运行时英文表按 Source 做原生参数格式化，不查其他同英文 Key 的译文。
Text.Tr 与 Localization:Tr 只接受定义对象，不做字符串重载；按英文反查语义 Key 的
旧路径已移除，Text.Mark 已删除。集中 TranslationDefinitions 和 CollectibleText
文案导出模块已移除；各文件顶层的动态 TranslationTexts 由工具独立收集。
配置翻译由工具生成和收集，不要求在业务接入中补转换、适配或兼容逻辑。

另提供独立的 `Text.TrSource(source)`，只按完整原文查询当前语言译文，不需要 Key。
内部调用 Roblox 原生 `Translator:Translate(game, source)`，不把原文当 Key；未加载、
缺译、查询失败或返回空串时直接返回原文。该入口不登记原文，不做模板参数格式化。
需要模板参数或同文不同义时继续使用 `Text.Tr(definition, arguments)`。
两个入口都复用现有翻译器及语言刷新事件；新增查询能力不改变静态文本、Generated
或配置的工具职责，也不改服务端提示协议。

服务端 `player:ShowLocalizedTips(TranslationTexts.Name, arguments, duration)` 发送
只含 Key/Source 的表，客户端保留定义和参数用于语言刷新，不重置显示计时。
数量参数在生产处按占位符准备，数量缩写显式使用 GameUtility.NumberToText；
提示接收端不再按旧 Key 做特殊格式化。嵌套业务动态名称可使用 itemDefinition；
配置名称只传 itemSource 原文，客户端按原文查询后作为 item，不另建翻译定义。
游戏业务动态消息使用定义对象；
Tool 通过 DisplayNameSource 属性传递配置原文，掉落消息使用 NameSource，客户端
统一用 Text.TrSource 查询已有译文；不为配置引用复制文案表或合成 Key=Source 定义。
引导配置仅携带 textId 等业务标识，显示端在自己的 TranslationTexts 中取定义；
旧引导存档由数据迁移根据当前步骤配置重建目标，不保留旧字符串翻译入口。
业务动态消息的定义留在对应脚本；静态名称和配置文案按工具流程处理，不借此扩大改造范围。
集中定义拆分后，重复使用的文案采用各文件模块前缀 Key；旧 Key 的历史译文不自动迁移，
需重新收集并通过显式映射和翻译发布流程处理，不能因 Source 相同直接搬用。
新 Key 的译文仍需经收集、比对和发布流程维护，不能自动套用旧英文 Key 的译文。

模板和参数分开，不先拼句子。数量缩写复用 GameUtility.NumberToText 并使用
`{value}`，整数使用 `{count:int}`；名称参数先在客户端翻译再传入整句。
显示结果不参与计算、存档或发奖。旧英文 Key 改为语义 Key 需显式映射，
不因 Source 相同自动搬译文；同 Key 改 Source 的旧译文需要复核。

## 发布与验证

从 Scripts 目录运行 `python -X utf8 Tools/check_translation_contract.py`，检查旧标记、
字符串翻译调用及旧名称协议是否回归。该检查只读、不执行 Luau；静态文案表合法性、
全局 Key 唯一性及收集覆盖仍需运行翻译工具收集器检查，动态参数须核对生产和消费链路。

文案定义、三路收集、云端发布和最终语言验收分别报告。工具产出完整 CSV、
比对合并及差异批次不等于已上传。编码任务不通过 Roblox MCP 维护翻译表，
不手工改翻译 CSV，不自动上传或启动试玩。

静态节点、配置及 Generated 已正确处理的文案不额外补定义或重复翻译；
仅为确认未正确处理的动态文本在接入脚本补充。采集与发布由工具负责，
收集或入云端不等于已有目标语言译文。
遵循 AGENTS.md 做当前任务验证，分别报告语法、Script Sync 核对与运行验收；
最终检查英文兜底、同英文不同 Key、参数、语言切换、长译文布局及二次翻译。

平台语义参考：[AutoLocalize](https://create.roblox.com/docs/reference/engine/classes/GuiBase2d/AutoLocalize)、
[ATC](https://create.roblox.com/docs/production/localization/automatic-translations)、
[脚本本地化](https://create.roblox.com/docs/production/localization/localize-with-scripting)。
