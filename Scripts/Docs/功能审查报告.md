## 全部功能清单

以下清单按现有 `Docs/功能验收清单.md`、入口脚本和配置整理。它描述代码当前设计的完整功能面，不代表本次已完成 Studio 或运行时验收。

### 1. 奖励与数据基础

1. **统一奖励结算**：`FSRewardComp` 统一处理金币、钻石、训练值、普通背包道具、武器/光环解锁、战利品、容量效果和活动奖励；批量奖励先预检，交换购买先验证消耗和奖励，失败不应产生部分结果。项目处理器位于 `ServerScriptService/Server/Handlers/RewardHandlers.luau`。
2. **玩家持久数据**：保存金币、钻石、重生次数、训练值、历史最高等级、世界资格、设置、商店升级、光环、武器、战利品、图鉴、活动、背包、引导和购买记录。同步字段通过 `S2C_PlayerStateSync` 下发客户端。
3. **初始赠送与迁移**：缺少钻石字段的新玩家获得 500 钻石，缺少武器字段时解锁 101 号木镐；旧档迁移补历史最高等级和离线福利基础字段。

### 2. 系统功能

1. **排行榜**：世界 1 至 3 的排行榜入口展示力量、重生和在线时长榜；支持头像、滚动、个人金色行、靠近按 E 查看和退出。当前排行榜仍以测试数据为主，未接入真实全服排名。入口：`CLeaderboardUICompClass.luau`、框架 `FSRankingServiceClass.luau`。
2. **设置界面**：主界面打开 `SettingsUI`；音乐和音效独立设置 0 至 100，显示光环只改变本机粒子可见性；音乐音量、音效音量、显示光环三个偏好由服务端保存并在重登后恢复。减少特效、通知、紧凑文字暂未接入。
3. **圣光礼盒**：按 `GiftData` 累计当天在线秒数，在 10/20/30/40/50 秒生成个人礼盒；未领取档位不阻塞后续档位，跨 UTC 日清理；服务端校验礼盒归属、落地、存活和距离，通过 `FSRewardComp` 发 5 钻石并防重复；客户端负责礼盒、圣光、按住 E 和奖励飞行动画。
4. **钻石货币商店**：钻石页按组只显示下一档训练倍率或随身容量；确认页提交商品 ID，服务端按当前档位和余额结算，重复请求不能重复升级；训练倍率和永久容量重生、重登保留；满经验的力量包不可购买。
5. **Robux 商品商店**：展示钻石包和周卡，平台价格通过 `MarketplaceService:GetProductInfoAsync` 读取；价格读取失败或商品 ID 未配置时禁购；客户端只发起平台窗口，服务端 `ProcessReceipt` 发奖并记录 `PurchaseId` 去重。
6. **小狗 NPC**：世界 1 前五区每批随机不同区域生成 3 只公共小狗；模型原地旋转、黄金描边和 E 交互；任意存活且已就绪玩家可竞争拾取，每只只成功一次，只增加 `GetDog` 任务进度，不进背包、不增加普通道具任务。
7. **世界传送**：世界 1 至 3 共用世界列表；服务端按历史最高训练等级校验世界 2、3 资格，按配置坐标传送并同步 `WorldIndex`；出生垫板只作落点标记，不启用随机出生。
8. **福利与活动**：包括离线训练、在线时长奖励、七日累计登录、每日钻石、每日任务、好友同服任务和两种周卡。进度、领取状态、好友去重、周卡剩余次数持久化；每日按 UTC 重置；容量不足时奖励资格保留；离线批次由服务端按离服时间生成且每日只能领取一次。
9. **训练基地**：进入 Training1 至 Training5 后由服务端按位置和重生次数判断是否解锁，自动训练并替代走路/击打收益；离开、传送、死亡或换角色停止原场地结算，不接受客户端倍率。
10. **武器商店**：世界 1 和世界 2/3 的小屋触发器打开统一武器页；服务端按 `ToolConfig` 读取价格和训练倍率，101 默认拥有并装备；金币购买永久解锁，较高倍率武器自动装备，相同或更低倍率保留当前装备，当前武器不能卸下；角色重生和重登恢复模型、攻击动画与拖尾。
11. **GM 管理**：开发者白名单才显示 GM 入口；可设置等级、重生、金币、钻石，按配置 ID 添加道具，重置数据和立即保存；服务端按请求者身份校验；加载失败时通过恢复处理器仅开放开发者的本人恢复。
12. **石头关卡**：客户端预测血量、自动挥镐、普通攻击和满血秒杀；服务端按等级差减伤、攻击频率、装备和位置校验命中；首次进区预生成普通、幸运或空格内容，离开重进不重抽；回基地按钮由服务端校验，边沿入库并恢复个人石头；无效命中回包撤销客户端预测。
13. **等级与训练**：走路、有效击打、空白区域点击、训练台、力量卡和离线奖励都进入真实训练值；服务端限速、封顶和计算倍率，客户端显示等级、力量、经验和实际收益飘字；重登恢复。
14. **战利品与存储**：战利品按服务端签发的唯一掉落 ID、道具 ID、价格、幸运状态记录；只允许归属玩家拾取；地面掉落过期移除；随身战利品回基地后进入 KV 收藏库存，不生成原生 Tool；随身容量和 KV 总容量分别校验；满容量时保留地上物品。
15. **钻石余额**：主界面同步显示钻石，余额持久化，首次缺字段时发放 500 钻石。
16. **道具出售**：世界 1 和世界 2/3 的出售小屋打开 `LootSellUI`；只展示已入库 KV 收藏品；服务端按稳定 `SellId` 校验，普通出售或消耗 103 号双倍出售卡后按重生金币倍率结算；成功删除库存、增加金币、释放容量并保留图鉴，失败不消耗卡。
17. **图鉴**：展示全部 `GameConfig.ItemData`；成功入库后按道具 ID 激活，普通和幸运版本共用一条记录；重复入库不重复增加种类；激活项显示名称和图标，未激活项隐藏。
18. **光环商店**：世界 1 和世界 2/3 的光环小屋打开统一界面；服务端按配置购买、解锁和装备；购买更高倍率自动装备，未装备时首次购买直接装备，当前光环再次点击可卸下；粒子由服务端复制到角色身体部位，重生和重登恢复，其他玩家可见。
19. **重生**：服务端保留达标校验、训练值归零、等级回到 1、重生次数增加、训练/金币倍率变化，货币、武器、光环、背包和图鉴保留。当前 `RebirthUI` 模板按验收清单仍缺失，客户端入口处于开发中状态。
20. **本地化**：项目维护英文源文案，通过稳定 Key、英文兜底和 Roblox 云端 Translator 支持其他语言；动态收藏品名称、品质、幸运提示、奖励提示和界面文本按当前语言刷新。

## 发现的问题

严重程度说明：P1 表示会阻断核心收益或支付；P2 表示明确的功能逻辑错误或功能不可用；P3 表示条件性风险、配置不一致或维护问题。

### P2：战利品容量判断使用 `>=`，最后一个容量格永远不能使用

- 位置：`ServerScriptService/Server/Player/SRockLevelCompClass.luau:563-567`、`ServerScriptService/Server/Handlers/RewardHandlers.luau:115-117`。
- 代码在拾取和统一奖励预检中都判断：`#stored + #loot >= capacity`。
- 当当前总数为 `capacity - 1` 时，再拾取一件后刚好达到容量，按容量语义应当允许；当前 `>=` 会提前拒绝。
- 影响：配置容量为 12 时，玩家最多只能存 11 件；普通拾取和通过 `FSRewardComp` 的批量奖励都会出现同样边界错误。
- 建议：判断“加入后是否超过容量”时使用 `#stored + #loot + 1 > capacity`，并为 `capacity - 1`、`capacity`、`capacity + 1` 增加逻辑测试。

### P2：GM 重置数据后默认武器没有恢复拥有权

- 位置：`ServerScriptService/Server/Player/SGMCompClass.luau:50-66`、`ReplicatedStorage/Scripts/Game/Shared/PlayerDataConfig.luau:114-120`、`ServerScriptService/Server/Player/SWeaponCompClass.luau:13-26`。
- `ResetData()` 将全部 table 字段恢复默认值；`WeaponData` 默认值是 `{owned = {}, equippedId = 101}`，其中 `owned["101"]` 仍为空。
- 101 号木镐的拥有权只在 `SWeaponCompClass:OnPlayerLogin()` 中补发。GM 重置不会再次调用该登录流程。
- 影响：重置后存档显示装备 ID 为 101，但默认武器不在拥有字典中；后续装备校验、商店状态和原生镐子可能互相矛盾，玩家可能无法再次正常装备木镐。
- 建议：重置时通过同一奖励入口补发 101 号武器，或把默认武器拥有权作为重置后的显式不变量写入 `WeaponData`，再刷新武器显示。

### P2：在线奖励发放 107 号 `NpcCard`，但服务端没有对应使用处理器

- 位置：`ReplicatedStorage/Scripts/Game/Configs/ItemConfig.luau:72-79`、`ReplicatedStorage/Scripts/Game/Configs/ActivityConfig.luau:139-148`、`ServerScriptService/Server/Handlers/ItemHandlers.luau:1-77`。
- 107 号道具声明 `UseHandler = "NpcCard"`，在线 5 分钟奖励会发放两张 107 号道具。
- `ItemHandlers` 只注册 `WeekCard`、`TrainingCard`、`ExpandableBackpackCard`，没有 `NpcCard`。`FXItemContextClass:CanUse()` 找不到处理器后会返回 false。
- 影响：玩家可以得到 107 号物品，但原生背包点击使用永远失败，相关 NPC 卡功能没有可执行路径。
- 建议：实现并注册 `NpcCard`，或者在活动配置中移除该奖励并明确替换物品，避免发放不可使用道具。

### P2：训练倍率实际可购买到 1024/2048，和验收规则“最高 512 倍”不一致

- 位置：`ReplicatedStorage/Scripts/Game/Configs/ShopConfig.luau:129-151`、`ReplicatedStorage/Scripts/Game/Configs/GoodsConfig.luau:189-205`、`ReplicatedStorage/Scripts/Game/Shared/CurrencyShop.luau:15-29`。
- `ShopConfig` 将 159/160 号商品列为 X1024、X2048，`CurrencyShop.GetNextGemGoods()` 会继续返回它们；服务端购买逻辑没有 512 倍上限。
- 影响：客户端在购买完 X512 后仍会显示并允许购买 X1024、X2048，实际产品规则与 `Docs/功能验收清单.md:45` 的“顺序购买至 512 倍（9 档）”冲突。
- 建议：如果 512 是产品上限，删除/隐藏 159、160 并在服务端增加上限校验；如果 1024/2048 是新设计，则同步更新验收清单、价格和所有 UI 文案。

### P2：Robux 商品没有配置 `RobloxProductId`，当前平台支付链路全部不可用

- 位置：`ReplicatedStorage/Scripts/Game/Configs/GoodsConfig.luau:1-96`、`ReplicatedStorage/Scripts/SetupProvider.luau:74-83`、`StarterPlayerScripts/Client/UI/CCurrencyShopUICompClass.luau:53-69`、`StarterPlayerScripts/Client/UI/CCurrencyShopUICompClass.luau:129-136`。
- 所有 Robux 商品配置只有业务用 `DevGoodsId`，没有有效的 `RobloxProductId`。
- `GetGoodsConfig(productId)` 只按 `RobloxProductId` 反查；UI 无法读取平台价格，会将所有 Robux 商品标记为 `unavailable`；服务端预检和收据处理也找不到商品。
- 影响：钻石包和周卡的 Robux 购买当前全部禁用，已经支付的真实商品在没有对应配置时无法进入正常发奖处理。
- 说明：现有验收清单已经把“未配置时禁购”写成产品条件，因此“禁购”本身是预期保护；当前状态仍属于支付功能未配置完成。另有一个代码缺陷：`SPurchaseReceiptService.luau:30-35` 在商品反查为 nil 时直接访问 `goods.BuyHandler`，虽然被 `pcall` 捕获，但会记录到账提示失败，建议显式判空。

### P3：配置包含未实现的旧 Robux 购买处理器

- 位置：`ReplicatedStorage/Scripts/Game/Configs/GoodsConfig.luau:3-11`、`ReplicatedStorage/Scripts/Game/Configs/GoodsConfig.luau:87-95`、`ServerScriptService/Server/Handlers/BuyHandlers.luau:4`。
- 商品 1 使用 `UnlockVip`，商品 201 使用 `SendRedPacket`，但当前购买处理器只包含 `AddGem` 和 `AddItem`。
- 影响：如果将商品 1 或 201 配置真实商品 ID 或被其他入口调用，`FXBuyContextClass:CanBuy()` 会因找不到处理器而拒绝，收据也会一直返回未处理。
- 建议：删除已废弃配置，或实现处理器并补充购买、限购、回执和失败回滚测试。

### P3：旧存档的嵌套字段没有统一补默认值

- 位置：`ReplicatedStorage/Scripts/Framework/Server/Player/FSPlayerObjectClass.luau:174-180`、`ServerScriptService/Server/Player/SPlayerObjectClass.luau:246-263`、`ServerScriptService/Server/Handlers/BuyHandlers.luau:11-22`、`ServerScriptService/Server/Handlers/CurrencyShop.luau:55-57`。
