# 界面来源与生成脚本

- 先定位目标界面的现有业务组件与对应导出脚本。当前生成目录为 `StarterPlayer/StarterPlayerScripts/Client/UI/Generated/`；结合脚本的 `Generated by UIEditor` 标记、`ScreenGuiName`、继承关系和导入元数据确认对应关系。仅有相似节点名或仓库中存在生成目录，不足以认定目标 UI 来自编辑器。
- **有对应生成展示类**：先读取该类、它依赖的共享基类和已有业务子类。业务组件放在 Generated 之外，继承对应展示类；沿用项目既有 require、类注册和组件挂载流程，只挂载业务子类，避免同一界面同时挂载展示类与业务子类。不要直接继承 FCUICompClass 绕过生成脚本，也不要复制生成脚本另写一份。
- 按实际代码复用已有节点查找、布局适配、展示刷新和按钮交互。新导出使用共享基类 `CUIView`；已有旧导出可能仍使用 `CUIEditorUICompClass`，按目标生成脚本实际依赖接入，不凭名称强行改写。共享基类提供 `GetRootNode`、`GetUIConfig`、`GetUIState`、`BindUIData`、`RefreshUI`、`EmitUIAction`、`OnUIAction` 和 `SetButtonEnabled`；只有目标展示类实际使用的接口才需要接入。业务子类提供真实配置、状态、数据订阅及动作处理，不把编辑器模拟数据或模拟动作当作游戏业务。
- 接入前读取展示类的数据契约、Render 和 EmitUIAction 调用，核对配置/状态字段、单位、稳定业务 ID、动作名及参数。游戏提供与该契约一致的真实数据；契约不完整时先明确缺口，不猜测字段，也不把预览中的奖励配置或领取状态当作真实业务。
- 覆写 Ctor、OnReady、Dtor 等生命周期时，检查父类实现并保留必要的 Super 调用及调用顺序。Ctor 先调用父方法，再准备配置与状态；OnReady 先调用父方法绑定展示节点，再建立数据订阅并执行首次刷新，按界面需求 Show 或 Hide。不要假设 BindUIData 或 Render 会自动执行；沿实际初始化链接入。已有 Activated 绑定通过 OnUIAction 接业务，不再给同一按钮重复 Connect；已有屏幕适配不重复叠加 UIScale。
- 导入不会自动修改 Main.client.lua 或玩家组件列表。业务模块先加载对应生成展示类，框架初始化后由客户端入口 require 业务模块，玩家对象再 AddComponent 业务类；生成类仅作为父类加载，不额外挂载。编辑器的接入脚本只用于模拟预览，不作为游戏业务导入。
- Generated 中的展示类、共享基类及导入元数据由编辑器管理，游戏业务不直接写入这些文件。需要调整生成的布局或交互时，优先修改编辑器源界面并重新导出/导入；若生成脚本缺少所需接入点，说明缺口，不另起一套展示实现。
- **普通界面，没有对应生成脚本**：沿用现有 FCUICompClass 或项目已有 UI 基类、原生节点和下述生命周期规则。不强行继承 CUIEditorUICompClass，不为其补造 Generated 文件，也不为了统一接法迁移已有界面。
- **确认由编辑器生成，但对应脚本缺失或与界面不匹配**：说明缺失或不一致之处，核对生成脚本要求的节点路径与实际 Studio 界面，并检查 default.project.json 是否仍映射旧的 StarterGui 源模板；旧源模板可能在 Rojo 同步时恢复旧布局。先解决导出包、节点或同步来源的不一致，再实现依赖它的代码；不要默默按普通界面重写，也不要仅替换父类让不匹配的脚本运行。游戏资格校验、发奖和动作结果仍由业务服务端负责，展示层只转发动作及必要业务标识，再按同步数据刷新。

# UI 生命周期

- 普通 UI 子类继承 FCUICompClass，提供 GetCompName 和 _rootNode，或覆盖 GetRootNode；编辑器界面通过对应生成展示类间接继承，复用其根节点获取方式。
- 基类已有 Show/Hide：ScreenGui 用 Enabled，GuiObject 用 Visible；只需要附加刷新时覆盖 OnShow/OnHide。
- Ctor 调用 Super 后获取已核对的节点，绑定事件；Show 不重新 Connect 或注册协议。
- WatchDataChanged 回放当前值；不重复手动初始化同一文案。
- RBXScriptConnection 用 TrackConnection；网络回调用 UnRegServerMsgCallback 解除，不能当连接处理。
- 覆盖 Dtor 必须调用 Super；清理自建实例、任务、动画与交互对象，只清理自己拥有的对象。
- 使用 ResetOnSpawn=false 的长生命周期模板，或明确处理重生后重新绑定；不能持有已销毁的 PlayerGui 克隆。
- 关闭动画仅在需求已有时保留，播完才隐藏；处理再次 Show 时旧回调隐藏新界面的竞态。
- 普通列表删除行时保留 UIListLayout/UIPadding；不要 ClearAllChildren 清掉布局器和模板。
