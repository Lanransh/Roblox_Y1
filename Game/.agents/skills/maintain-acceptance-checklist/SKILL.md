# 维护功能验收清单

维护 `Game/Docs/功能验收清单.md`（以 Game 为工作目录时为 `Docs/功能验收清单.md`），让用户知道当前有哪些功能需要验收。它是已实现功能的验收索引，不是开发任务、未来计划或设计文档。

## 收录范围与粒度

清单以一个玩法系统为整体验收单位，不按代码文件、函数、提交或开发步骤列项。完成玩法功能后，更新其所属系统的功能项，以及有实际数值规则时对应的数值项；同一系统已有条目时更新原条目，不为每次改动追加一条。

先判断改动是否新增、删除或改变玩家可感知的玩法流程、规则、状态，或改变公式、收益、消耗、概率、成长等数值结果。符合时才维护相应系统条目；纯框架整理、添加日志、开发工具、注释或不影响玩法与数值的重构不新增条目，也不机械取消勾选。框架或公共代码变更若实际影响玩法，则维护受影响的玩法系统，不把框架或日志本身列为玩法。无法确认影响时，将可能受影响的已有系统项取消勾选并说明待确认原因，不虚构新系统。

## 盘点与更新

1. 读取现有清单、当前任务改动和 Game 服务目录中的相关代码、配置及实际功能入口；需要读取场景或 UI 节点时，按工作区规则通过 Roblox MCP 查询当前实例树和节点属性。清单不存在或尚未盘点时，盘点当前项目已实现的系统与功能后创建；已有清单时增量维护受影响项，用户要求全面盘点时再检查全项目。
2. 只记录当前实现可证实的功能。不能仅凭对话记忆、设计文档或参考项目列功能；未实现的计划、空壳入口和占位按钮不作为已实现功能。部分实现只描述实际可用的部分。
3. 在“系统功能验收清单”和“数值验收清单”两部分中，以玩法系统为单位组织 Markdown Checklist。功能项描述当前系统的流程、规则和状态结果；数值项描述该系统已实现的公式、收益、消耗、概率或成长等规则及依据。每项附简短操作入口或代码位置。数值部分引用对应配置或公式，不复制整份配置表；没有独立数值规则的系统不强行添加数值项。
4. 新增功能默认使用 `- [ ]`。改动影响玩法行为或数值结果后，将对应系统及受影响关联系统在相应部分的条目改回 `- [ ]`，注明“待重新验收”及原因；修复 bug 或重构若影响玩法行为或数值结果，也不能沿用受影响项的旧勾选；只影响其中一部分时保留另一部分未受影响项的状态。配置变化影响行为或数值时同样处理。根据调用关系和状态、数值依赖判断影响范围；范围不明时将可能受影响项保持未勾选，并说明待确认范围。
5. 同步修正已改变的功能描述；已移除的能力从当前清单条目中移除，不保留为当前功能。未受影响项保留原状态，不把清单改成变更历史。

## 验收状态

- `- [ ]` 表示尚未通过当前实现的验收，包括未验收、待重新验收、发现偏差或无法验证；用简短备注区分原因。
- `- [x]` 只表示实际验收已确认符合预期，只能由用户亲自勾选，或用户明确要求 AI 勾选指定项时由 AI 代为勾选。AI 不得自行勾选；即使实际验收或自动测试通过，也只能记录结果并保持未勾选。“执行验收”不等于“授权勾选”。
- 用户授权勾选只适用于指定项的当前实现；后续改动导致取消勾选后，AI 必须获得用户新的明确指令才能重新勾选。取消受影响项的勾选由 AI 自动执行，无需用户另行授权。
- 验收预期来自用户要求或已确认的设计规则，不能根据当前代码行为反推“正确答案”。清单中的事实描述只证明功能存在，不证明它符合预期。
- 执行验收或记录用户明确给出的验收结论时，注明日期、验收人或执行者、方式与结果，必要时链接测试输出或运行记录。证据必须对应当前实现和该条目的范围；只验收系统的部分能力时，将结果记在该系统项下，整体保持未勾选，直到对应功能或数值范围验收完整。
- 未实际验证、预期不明确或结果不符合预期时保持未勾选，并注明缺少的依据、阻碍或差异。旧证据不能充当修改后的验收结果。
- 遵循工作区的验证限制：默认只做 Luau 编译/语法验证及相关 Rojo 构建；用户明确要求运行测试或试玩时可按授权执行。没有实际运行证据的条目保持未勾选；构建成功不能代替玩法、云存档或真实支付验收。

## 文档形式

文件开头说明“仅记录当前已实现功能；勾选表示验收通过，只能由用户或用户明确授权的 AI 勾选；代码改动后受影响项自动取消勾选，需重新验收”。正文必须包含“系统功能验收清单”和“数值验收清单”两部分，各自按玩法系统列项。具体步骤和证据按需补充，不预填示例游戏功能。

设计规则以用户确认的项目现有设计文档为准，清单引用相关段落，不复制一份设计，不假设文档存在。验收清单的维护独立于设计文档是否需要更新：修复代码使其符合原设计，也必须取消受影响项的验收勾选。

## 完成检查

- 每项都能在当前项目找到实现或功能入口，没有混入计划、已移除能力或其他项目功能。
- 本次完成的玩法已更新到所属系统的功能项及适用的数值项，没有混入纯框架或日志等开发事项；受影响的系统及关联项已恢复待验收状态；勾选项有对应当前实现的实际验收依据；AI 新增勾选有用户对相应条目的明确授权。
- 引用的项目内路径有效，交付时简述新增、待重新验收和无法验证的项目；只维护清单时，不声称已完成实际功能验收。
