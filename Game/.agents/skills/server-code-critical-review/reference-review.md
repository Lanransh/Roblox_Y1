# 输出格式

## 基本要求

- 按点作答。
- 分点换行。
- 先写发现的问题，再写总结。
- 按优先级从高到低输出。
- 不要把多个问题写在同一段里。
- 每个问题都要说明位置、原因、风险、建议。
- 没有确认的问题，要写成“未确认风险”或“建议确认”，不要当成确定 Bug。

## 有问题时

按下面格式输出：

```markdown
1. [严重/高/中] `文件路径:行号` 问题标题

   问题：
   这里写具体问题。

   原因：
   这里写为什么会出现这个问题。

   风险：
   这里写会导致什么后果。

   建议：
   这里写修复方向。
```

## 有遗漏项时

按下面格式输出：

```markdown
1. [遗漏项] `文件路径:行号` 遗漏标题

   遗漏：
   这里写缺少了什么检查、配置、字段、状态或处理。

   风险：
   这里写可能造成什么后果。

   建议确认：
   这里写需要继续确认哪个文件、函数或流程。
```

## 没发现明确问题时

按下面格式输出：

```markdown
本次未发现明确的高危漏洞或严重 Bug。

未确认风险：
1. ...
2. ...
```

## 结论要求

- 如果有明确问题，不要只写“建议优化”。
- 如果问题会导致漏洞、重复发奖、数据错乱、扣费不发奖、玩家数据损坏，要明确标成严重或高。
- 如果只是代码风格、命名、普通重构建议，不要输出。
