# 个人石头隐藏道具接入计划（供 Luna 执行）

## 1. 任务与范围

目标：把当前“击破石头时随机开奖”改成“玩家首次进入区域时，服务器预先确定该玩家石头里的普通和幸运道具；击破只揭露结果；回基地补满石头并开始新轮次”。

本文件是实施计划，不表示功能已经实现或测试通过。执行前阅读仓库及 `Game/AGENTS.md`，按其中的路由完整读取本次需要的 Skill。禁止凭旧项目 API 编写 Roblox 代码。

用户明确限制：

- 不检查、不读取、不修改 XLSX，包括配置文档中的临时 Excel 文件。
- 本次不接入图片：不上传图标、不替换 IconId、不生成图片、不修改贴图或图片 UI。继续复用现有模型和文字表现。
- 不做公共地面定时刷新，不迁移 Y3 的公共刷新管理器。
- 不修改框架核心、不重做背包、不顺带调整商店或其他玩法。
- 文件修改必须使用 Codex 可追踪编辑工具，优先 `apply_patch`。终端仅搜索、读取、验证和检查 diff，不通过脚本或重定向写代码。

## 2. 核心规则与实施约定

用户明确确认的核心是：按区域预生成、个人独立、仅本次服务器游玩保存、每轮包含幸运、回基地补石头。以下同时列出本计划的具体实施约定；其中数量分配、揭露后拾取和回基地重抽是沿用前文建议的方案，不应描述成用户逐项确认过的要求。

1. 每个玩家的石头内容、已击破状态和掉落领取状态独立。
2. 首次进入某区域，服务器生成该玩家本轮该区域的内容。不能在敲击或击破时才随机生成。
3. 每次区域初始化同时包含普通和幸运道具，不存在独立幸运计时刷新。
4. 普通和幸运占据不同石头，同一块石头最多藏一件道具。允许不同石头抽到相同道具。
5. 未分配道具的石头是确定的空石头，不是“尚未初始化”。
6. 本轮离开区域再进入，不重新生成、不补石头、不重抽。
7. 回基地补满个人石头，结束上一轮；下次进入区域重新生成内容。
8. 个人场景状态仅保存在服务端玩家组件内存，不写入 DataStore 或持久化玩家字段。退出清理，重新加入重新生成。
9. 已拾取战利品和正式背包沿用现有处理，不因清理场景状态而被删除。

### 本计划采用的默认细节

以下是为实现闭环提出的默认值，不能冒充用户已逐项确认；实施前在说明中列出，有不同意见再调整：

- 幸运与普通共用区域奖池，幸运只增加价格倍率，不额外改变品质概率。
- 未击破前不显示哪个石头藏道具、哪个石头是幸运；揭露后才显示幸运信息。
- 回基地清理上一轮未拾取掉落；已拾取但因满包未能入库的战利品仍保留。
- 角色死亡不等于回基地。死亡本身不重抽；若重生位置在基地，则由基地进入逻辑结束该轮。
- 首次出生在基地不需要反复增加轮次。只有离开基地后再返回，才执行一次回基地重置。
- 未击破石头的部分血量不新增服务端持久状态：正常区域卸载/重载沿用当前客户端血量缓存；角色更换时恢复未击破石头的满血，并清除旧角色对应的攻击凭据，但保留已生成内容、已击破状态和场景掉落。角色更换不是新道具轮次；若随后进入基地，再按基地规则重置。

## 3. 配置契约（仅操作 Lua，禁止检查 XLSX）

优先复用当前 `Game/ReplicatedStorage/Shared/Config/GameConfig.lua` 的已有字段，不新建另一套同义配置：

| 字段 | 新流程语义 |
| --- | --- |
| `AreaConfig[areaId].NormalRefreshCount` | 每轮区域初始化藏入的普通道具数量 |
| `AreaConfig[areaId].LuckRefreshCount` | 每轮区域初始化藏入的幸运道具数量 |
| `AreaConfig[areaId].LuckRefreshRate` | 每件幸运道具独立抽取的倍率区间 |
| `AreaRefreshData` 的 `AreaId`、`RewardPool` | 区域奖池，`x` 为道具 ID，`y` 为权重 |
| `ItemData[itemId].Pirce` | 基础价格，保留现有拼写，禁止全项目顺手改名 |
| `ItemData[itemId]` 的模型、品质等字段 | 道具定义，必须与实际模型映射一致 |

新流程不读取 `NormalRefreshInterval`、`LuckRefreshInterval` 或 `ObjectType`。保留旧字段，不为清理未使用字段扩大修改范围。

当前 `RockCollectible.lua` 中的 `DropChance`、`MinPrice`、`MaxPrice` 不再参与隐藏内容生成；检查实际引用后只清理本次确实废弃的常量。

价格在区域生成时固定：普通为基础价格，幸运为基础价格乘以抽到的倍率。优先沿用项目已有倍率精度；价格计算与显示分离，不用格式化字符串存价格，不擅自取整。

### 配置校验及不能猜测的部分

- 数量必须是非负整数，普通加幸运不超过区域格子数；违反时明确报配置错误，不静默截断或改数值。
- 奖池 ID 必须能找到道具定义及可用模型；权重非负，总有效权重大于零。
- 若同一区域有多条 `AreaRefreshData`，先定位实际数据及既有约定，不能擅自平均混合或取第一条。
- 当前旧道具 ID、名称和模型存在可能不一致的映射，当前掉落又使用 `Collectibles167`。先只读定位 Lua 和模型映射；不得按名称猜对应关系，不能把道具 ID 当模板列表下标。
- 检查 GameConfig 的实际加载入口，复用已生效配置；不要凭目录名称引入第二份配置。
- 核实 `AreaConfig` 的键是否确实等于 `AreaId`，以及当前仅世界 1 的区域编号和配置编号是否一致；不成立时按 `AreaId` 建最小索引，禁止直接猜表下标。
- 幸运数量大于零时，倍率区间必须包含两个有限正数且下限不大于上限；基础价格必须为有限非负数。普通和幸运数量均为零的区域可直接登记为空初始化区域，不要求执行奖池抽取。
- 模型映射无法确认时，给出缺失 ID/映射清单并请求用户确认，不退回随机模型或随机价格来掩盖问题。
- 如需修改生成式 Lua 配置，仅改必要字段，并说明未来重新导出 XLSX 可能覆盖该改动；本次不操作 XLSX。

## 5. 服务端状态与生成约束

建议逻辑结构（不是必须照搬的代码 API）：

```text
玩家组件
  Round：当前轮次
  Areas[areaId]：存在即代表本轮区域已初始化
    Contents[cellId]：仅有道具的格子，保存已确定奖励
    Broken[cellId]：已经通过服务端击破校验的格子
  已有命中记录及掉落记录
```

奖励记录至少包含稳定道具 ID、可重建的模型标识、最终 Price、IsLucky、LuckRate。普通 `LuckRate = 1`；幸运身份使用明确标识，不能只用倍率是否等于 1 判断。

生成步骤：

1. 从服务端角色位置判断实际进入区域，复用现有区域边界，包含高度检查。
2. 区域本轮已初始化则直接返回；不能以 Contents 是否为空判断初始化状态。
3. 在有效格号中不放回抽取普通数量加幸运数量个位置。
4. 按区域权重分别抽道具，确定模型、倍率和价格；先完整构建，再登记为已初始化。
5. 存入该玩家组件，不向客户端发送未揭露奖励清单。

配置加载、模型解析等可能等待的操作应尽量在初始化准备阶段完成。区域生成和登记应不让出执行权；若确需等待，必须有同一区域初始化中的防重入状态，并在等待返回后核对玩家仍在线且轮次未改变。失败不能留下半份区域内容，也不能让高频 Tick 持续重试、刷日志或阻断入库；错误配置明确标记为不可生成并报告原因。

进入检测可复用现有位置 Tick，无需新增每玩家无限循环。首次合法命中到来但位置 Tick 尚未运行时，可在同一服务端位置验证之后幂等初始化，防止正常玩家遭遇时序问题；该路径仍是区域初始化，不是按命中重抽。

## 6. 击破、拾取与同步

- 保留 `RecordHit` 中的轮次、格号、位置、持镐、存活、攻击频率和有效伤害检查。
- 击破请求必须通过现有服务端伤害凭据；不接受客户端上报奖励、价格、倍率或位置。
- 删除击破时的概率开奖，改为读取本轮区域对应格子的确定内容。
- 空石头也登记为已击破；重复击破不产生奖励。
- 先占用该格的揭露资格，再产生唯一掉落记录，防止重复请求多次领奖。配置或模型失败应在预生成阶段暴露；运行时创建仍失败时保留原奖励及可重试状态，不重抽、不把创建失败当奖励已领取。无需新增通用事务框架。
- 核查掉落创建路径中的等待点。回基地或离服可发生在等待期间，返回后必须检查原轮次和组件存活状态；旧轮次的模型、HUD、提示和任务立即释放，不能在新轮次登记旧奖励。
- 复用现有 `ProximityPrompt`、弹起/漂浮、掉落有效期、距离和容量校验，不另写一套拾取协议。
- 奖励数据以服务端记录为准，实例 Attributes 只供展示，保留拾取锁及超时检查。
- 幸运属性随临时战利品和入库 ExtraData 保留；Tool 重建不重抽价格。老数据缺少幸运字段时按普通处理，不能使旧背包失效。
- 不把所有人的隐藏内容复制到 ReplicatedStorage。当前服务端掉落模型只限制拾取归属，不等于仅本人可见；本次至少保证他人无法领取，不擅自重构成客户端掉落架构。若用户要求严格仅本人可见，再单独确认范围。
- 客户端区域距离卸载/重载、角色重生和准备完成握手时，恢复本轮自己的已击破状态；不能因模型重建恢复已经领过的石头。
- 若需补同步，仅发送轮次和已击破格号等必要状态。旧轮次消息不能影响新轮次。
- 轮次重置与同轮状态恢复必须分开处理：同轮快照是恢复已击破列表，不能调用会清空本轮状态的重置入口。角色更换清理命中凭据时，同步清掉客户端待确认命中，避免残留预测伤害用于新角色。

## 7. 回基地重置（重点）

当前 `Tick` 和 `RestoreRocks` 需要核查并调整，不能仅用“有命中记录”判断该轮是否需要重置：玩家进入区域即已生成内容，即使没敲石头也应能结束该轮。

基地进入边沿处理：

1. 沿用当前基地边界判定，识别从基地外返回基地。
2. 沿用入库流程；入库失败时保留剩余 `RockLoot`。
3. 一次性清理旧掉落、个人区域内容、命中/领取记录及相关任务，递增轮次。
4. 通知该玩家恢复全部个人石头。下次进入区域才生成内容，不在基地提前抽全图。
5. 玩家停留基地期间，不重复清理或递增轮次；仍允许既有满包处理/入库逻辑按实际需要执行。

保留相关组件事件协作。不要为改石头规则改变训练收益、等级、出售、背包容量或重生数值。

## 8. 实施顺序与阶段检查

1. **只读定位**：确认配置加载、奖池/模型映射、协议、基地与重生调用链、客户端重建逻辑。
   - 检查：列出可用映射与缺失项，明确最小文件范围；不读 XLSX。
2. **预生成内容**：新增个人区域内存并实现幂等初始化。
   - 检查：数量正确、位置不重复、普通幸运分离、空区域不会重复初始化。
3. **击破揭露**：替换开奖，串接既有掉落/拾取/入库。
   - 检查：无击破重抽、无重复奖励、最终价格和幸运信息一直一致。
4. **轮次与基地**：实现一次返回一次重置，处理角色及客户端恢复。
   - 检查：区域重进不补、回基地补满、站基地不反复重置、旧请求失效。
5. **文档与验证**：更新核心规则验收清单，执行授权范围内的验证和 `git diff --check`。

每阶段只修改直接相关代码。发现无关旧问题只说明，不顺手修复。已有用户改动必须保留，特别是当前 GameConfig.lua 等配置文件；先查看 diff 再做小范围 patch。

## 9. 验收场景

以下是后续需要验证的场景，不代表本计划已授权启动试玩：

- A/B 两玩家同一区域，击破与领取互不影响。
- 区域初始化普通 N 件、幸运 M 件，分布于 N+M 个不同格子；未中奖格子不会重新开奖。
- 进入同一区域多次，内容不变；远离后客户端重新加载仍不恢复已击破格子。
- 同一格重复击破、重复拾取、超时拾取、远程拾取均不能重复或非法领奖。
- 道具、价格和倍率在生成后固定，客户端篡改 Attributes 不影响奖励。
- 回基地补满并清除上一轮未拾取掉落；已携带及未成功入库道具不丢失。
- 在基地连续停留不反复增加轮次，离开再返回只增加一次。
- 只进入区域但没有敲击，回基地也能结束该轮。
- 空手死亡、挖掘后死亡、基地重生的状态符合规则；旧轮次消息不影响新轮。
- 角色更换后未击破石头满血、旧攻击凭据失效，已击破石头和隐藏奖励不重抽；基地外重生与基地内重生分别验证。
- 区域初始化或掉落创建发生等待时回基地/离服，无旧轮奖励晚到、半份区域记录或遗留模型。
- 错误数量、无效倍率、缺失模型明确报告且不发错误奖励，不造成位置 Tick 高频报错；零道具区域只初始化一次。
- 老收藏品 ExtraData 无幸运字段仍能重建 Tool。
- 离服清理任务、补间、连接、场景掉落和个人区域内存；重新加入没有旧场景残留。
- 无地面定时刷新、无幸运倒计时任务、无敲击开奖、无图片接入。

## 11. 明确禁止的错误实现

- 继续在 RollDrop/击破函数中随机挑道具，只把函数改名为“读取内容”。
- 每次进入区域、每次敲击或发现奖池内容为空时重新初始化。
- 添加定时幸运刷新、公共地面生成、回基地外自动补石头。
- 玩家站基地时每个 Tick 清空状态并重抽。
- 信任客户端奖励、价格、倍率、击破血量或未验证的位置。
- 为每个玩家在服务端复制整张石头地图，或广播未揭露道具列表。
- 奖池模型找不到时静默换成随机收藏品，掩盖配置错误。
- 清理场景时清空 RockLoot 或正式背包。
- 未确认映射就批量改配置、检查 XLSX 或接入图片。
