# 项目本地化

## 文案来源与优先级

英文是源语言和离线兜底语言。文案统一维护在 `ReplicatedStorage/Scripts/Game/Shared/Localization.csv`，Rojo 将其同步为原生 `LocalizationTable`；同目录的 `Localization.meta.json` 设置 `SourceLocaleId = en-us`。

项目只维护英文，其他语言交给 Roblox 自动翻译。客户端显示顺序：Roblox 云端译文 → 本地英文。英文玩家直接使用本地英文。云端 Translator 在后台加载，最多尝试 3 次，不阻塞界面；加载失败、缺少译文或译文格式错误时使用英文。未知 Key 或不符合模板的参数显示通用英文错误提示，并输出开发日志。

`Localization.Changed` 在云端加载完成、玩家语言变化时触发。已接入的 UI 据此刷新当前文字；提示刷新保留原有显示期限。翻译结果直接写入 UI 的节点设置 `AutoLocalize = false`，避免再次自动翻译。

## 维护英文文案

CSV 每行是一条文案：

| 列 | 用途 |
| --- | --- |
| Key | 稳定标识，例如 `Loot.Deposited`；代码引用此列 |
| Source | 英文源文案，必须填写 |
| Context | 自动匹配 UI 源文案时的节点上下文；Key 调用可留空 |
| Example | 参数示例或译者参考 |

本地表只保留以上四列，不维护中文或其他语言列。如果以后需要修正自动翻译，在 Roblox 云端翻译门户修改对应译文；模块仍通过同一个云端 Translator 读取。

保存为 UTF-8 CSV。含英文逗号、双引号或换行的单元格必须按 CSV 规范引用；单元格中的双引号写为两个双引号。新增 Key 后通过 Rojo 同步或构建，使英文兜底随代码一起发布。

## 参数替换

使用 Roblox 原生格式，不先拼成完整英文或中文再翻译：

- `Strength: {value}`：字符串参数，可以传入 `GameUtility.NumberToText` 的结果。
- `Loot stored: {count:int}`：整数参数。
- 未来物品提示可写 `Picked up {itemName}`：先翻译物品名称，再传入字符串参数。

译文保留相同参数名和格式标签，可以调整参数位置，也可以多次引用同一参数。整句不使用格式化字符串作为计算、存档或发奖依据。

客户端显示提示：

```lua
local commonUI = self:GetPlayerObject():RequireComponent("FCCommonUIComp")
commonUI:ShowLocalizedTips("Loot.Deposited", {count = 3})
```

客户端获取文本：

```lua
local commonUI = self:GetPlayerObject():RequireComponent("FCCommonUIComp")
local text = commonUI.Localization:FormatByKey("Main.Strength", {
    value = GameUtility.NumberToText(strength),
})
```

服务端玩家组件发送提示：

```lua
self:GetPlayerObject():ShowLocalizedTips("Loot.Deposited", {count = deposited})
```

弹窗沿用现有回调等参数，并可使用 `DescKey`、`Arguments`、`ConfirmKey`、`CancelKey`：

```lua
commonUI:ShowTooltips({
    DescKey = "Loot.Empty",
    ConfirmKey = "Common.Close",
})
```

直接使用翻译模块时，通过 `require(...).New(Players.LocalPlayer)` 创建对象，订阅其 `Changed` 信号；结束时调用 `Destroy()`。现有 UI 复用通用组件的翻译对象，不要每个界面重复创建云端 Translator。

## Roblox 自动翻译

模块读取 Roblox 已生成的云端译文，不会在运行时调用外部机器翻译，也不会替你上传文案。

1. 在 Creator Dashboard 打开体验的 Localization，将源语言设置为 English。
2. 在翻译表中导入项目的 `Localization.csv`。Key 必须保留；只靠自动文本采集无法保证动态提示的 Key 条目存在。
3. 开启 `Use Translated Content`，为目标语言开启体验内文案自动翻译。固定模板文字需要自动采集时，另开启文本采集。
4. 等待云端生成译文。Roblox 通常仅为缺少译文的条目生成自动译文；人工译文按平台规则锁定，避免被自动更新覆盖。
5. 需要时在云端翻译门户校对关键译文，无需将译文下载到本地项目维护。

修改 Source 或新增 Key 后，重新导入对应条目，并将本地英文随游戏发布。导入时检查平台对现有译文的处理，保留已经审核的云端译文。CSV 中的 Key 保持稳定。

官方参考：[自动翻译](https://create.roblox.com/docs/production/localization/automatic-translations)、[翻译表维护](https://create.roblox.com/docs/production/localization/manual-translations)、[脚本本地化与参数](https://create.roblox.com/docs/production/localization/localize-with-scripting)、[Rojo CSV 同步](https://rojo.space/docs/v7/sync-details/)。

## 已接入与待迁移

已接入：主界面力量和满级文案、开发中提示、战利品弹窗标题和空列表提示、通用弹窗按钮、背包总容量提示、战利品背包满提示、存入数量提示及未能全部存入提示。

待迁移：167 个收藏品名称及品质、拾取成功提示、原生背包名称、默认玩家排行榜列名和 Studio 固定 UI 模板。其现有中文内容不属于模块的英文兜底文案，不能视为全游戏已经完成英文迁移。模板中的现有中英文混用需要单独整理；物品名称迁移前不要直接翻译模型名或存档里的 `TemplateName`。客户端目前按“免费镐子”查找工具，也需要先改用稳定标识再本地化显示名。

云端开关和上传尚需在 Creator Dashboard 完成。编译与 Rojo 构建不能证明实际翻译已生成；运行验收应覆盖英文、目标云端语言、缺失译文、参数变化及游戏内切换语言。
