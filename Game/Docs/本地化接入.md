# 英文源文案与 Roblox 自动翻译

项目只维护英文源文案，其他语言交给 Roblox 云端自动翻译。显示顺序为云端译文 → 本地英文，英文玩家直接显示本地英文。云端请求在后台进行，失败或缺少条目不影响英文显示。

框架提供 `FC.Localization` 翻译入口和 `ReplicatedStorage/Scripts/Framework/Shared/Localization.csv` 通用英文表。表内只有确认、取消、关闭和通用错误提示，没有任何游戏业务文案。Rojo 将 CSV 同步为 `LocalizationTable`，源语言为 `en-us`。

## 业务接入

框架初始化后创建一个由项目客户端统一持有的翻译对象，各个 UI 复用该对象：

```lua
local FC = _G.FC
local translation = FC.Localization.New(game:GetService("Players").LocalPlayer)
local text = translation:FormatByKey("Common.Close")
```

项目需要业务 Key 时，将通用 CSV 及同名 `.meta.json` 复制到项目自己的公共目录，保留通用条目并添加英文业务条目。通过 `FX.Loader` 取得项目的 `LocalizationTable`，传给 `FC.Localization.New(player, sourceTable)`；不要把业务文案写进框架表，也不要在每个界面重复创建翻译对象。

动态文本使用原生参数模板，例如 Source 为 `Items stored: {count:int}`，调用 `translation:FormatByKey(key, {count = 3})`。数量缩写由项目已有的统一数值方法生成，再作为字符串参数传入 `{value}`。禁止先拼接完整句子再翻译。

订阅 `translation.Changed` 刷新当前文案。翻译后的 UI 文本关闭 `AutoLocalize`；固定英文 UI 可使用 Roblox 自动本地化。释放客户端所属对象时，断开 UI 的 Changed 连接，并调用 `translation:Destroy()`，取消后台请求及语言监听。模块不会自动改写现有 UI、创建网络协议或修改存档。

## 云端设置

在 Creator Dashboard 将体验源语言设为 English，导入实际使用的英文 CSV（保留 Key），开启 `Use Translated Content` 和目标语言自动翻译。新增或修改英文 Key 后再次导入；动态 Key 不能只依赖自动文本采集。固定 UI 可开启文本采集。若将来需要校对，在云端翻译门户修改，不维护本地多语言字典。

云端开关和 CSV 上传需要按每个体验配置。模块只读取已生成的译文，不在运行时生成机器翻译，不调用外部翻译接口。平台译文生成及实际语言切换需要试玩验证；构建成功不代表云端翻译已启用。

原生 Tool、默认排行榜、图片内文字需要按显示入口另行处理，不假设自动采集覆盖；物品 ID、模型名和存档标识保持稳定。

参考：[Roblox 自动翻译](https://create.roblox.com/docs/production/localization/automatic-translations)、[原生参数与语言切换](https://create.roblox.com/docs/production/localization/localize-with-scripting)。
